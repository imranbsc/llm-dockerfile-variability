```Dockerfile
# Use the official .NET Core SDK runtime as a parent image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the solution file and restore the dependencies
COPY *.sln ./
COPY . .

# Restore the dependencies
RUN dotnet restore

# Build the solution
RUN dotnet build -c Release

# Create a directory to hold the output
RUN mkdir /app/out

# Copy the built output to the output directory
COPY --from=build-env /app/bin/Release/net6.0/*.dll /app/out

# Use the official .NET Core runtime as a child image
FROM mcr.microsoft.com/dotnet/runtime:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the runtime and the output DLL to the container
COPY --from=build-env /app/out/dotnet-worker.dll .
COPY --from=build-env /app/out/worker.exe .

# Expose the default port for the Worker Service
EXPOSE 5001

# Run the Worker Service
CMD ["worker.exe"]
```

**Explanation**:
- The Dockerfile starts with the official .NET Core SDK runtime image as the parent image, which provides the necessary tools and libraries to build and run .NET applications.
- The working directory in the container is set to `/app`, where all the build artifacts will be stored.
- The solution file and all the project files are copied to the container, allowing for a clean and reproducible build environment.
- The dependencies are restored using `dotnet restore`.
- The application is built in release mode using `dotnet build -c Release`.
- A directory `/app/out` is created to hold the output of the build process.
- The built output DLLs and the `worker.exe` are copied from the build container to the host container.
- The runtime and the output DLLs are then copied to the host container, and the container is set to expose the default port for the Worker Service (5001).
- Finally, the `worker.exe` is executed as the command to run the application.
