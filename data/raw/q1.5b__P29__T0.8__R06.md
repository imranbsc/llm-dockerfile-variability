```Dockerfile
# Use an official .NET SDK runtime as a parent image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container to /app
WORKDIR /app

# Copy the csproj file to the container
COPY *.csproj ./app/

# Restore the NuGet packages
RUN dotnet restore

# Copy the rest of the project files to the container
COPY . ./app/

# Publish the application
RUN dotnet publish -c Release -o /app/publish

# Define the final image name
FROM mcr.microsoft.com/dotnet/aspnet:6.0

# Set the working directory in the container to /app
WORKDIR /app

# Copy the published application from the build-env container to the final image
COPY --from=build-env /app/publish .

# Expose the default HTTP port
EXPOSE 80

# Define the command to run the application
CMD ["dotnet", "YourApplicationName.dll"]
```

In this Dockerfile, we start with an official .NET SDK runtime as a parent image. We then set the working directory in the container to `/app` and copy the `.csproj` file to the container. We restore the NuGet packages using `dotnet restore`. Next, we copy the rest of the project files to the container and publish the application using `dotnet publish`. After that, we define the final image name and set the working directory in the container to `/app`. We copy the published application from the build-env container to the final image and expose the default HTTP port. Finally, we define the command to run the application using `dotnet YourApplicationName.dll`.
