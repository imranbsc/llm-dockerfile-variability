```dockerfile
# Use a base image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the csproj file
COPY *.csproj .

# Restore the NuGet packages
RUN dotnet restore

# Copy the rest of the project files
COPY . .

# Add the Quartz.NET package
RUN dotnet add package Quartz

# Set the environment variable for Quartz.NET configuration
ENV QUARTZ_JOBSTORE_TYPE=Memory

# Set the Quartz.NET job data
ENV QUARTZ_JOB_DATA_FORMAT=JSON

# Create a scheduled task in Quartz.NET
RUN dotnet add Quartz job --name "MyJob" --type MyNamespace.MyJob --config MyJob.config

# Expose the Quartz.NET scheduler
EXPOSE 5000

# Run the scheduled batch job
CMD ["dotnet", "QuartzScheduler.dll"]
```

**Explanation**:
- The `FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env` line uses the latest version of the .NET SDK as the base image.
- The `WORKDIR /app` sets the working directory for the container.
- The `COPY *.csproj .` copies the `*.csproj` file to the container.
- The `RUN dotnet restore` restores the NuGet packages required by the project.
- The `COPY . .` copies the rest of the project files to the container.
- The `ADD Quartz.NET package` adds the Quartz.NET package to the project.
- The `ENV QUARTZ_JOBSTORE_TYPE=Memory` sets the Quartz.NET job store type to `Memory`, which is suitable for development purposes.
- The `ENV QUARTZ_JOB_DATA_FORMAT=JSON` sets the format of the job data.
- The `RUN dotnet add Quartz job --name "MyJob" --type MyNamespace.MyJob --config MyJob.config` adds a scheduled task named "MyJob" to Quartz.NET.
- The `EXPOSE 5000` exposes the Quartz.NET scheduler port.
- The `CMD ["dotnet", "QuartzScheduler.dll"]` runs the Quartz.NET scheduler in the container.
