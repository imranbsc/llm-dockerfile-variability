Here's a Dockerfile for a server-rendered web application built in Node.js using Next.js:

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy the package.json and package-lock.json files from the host to the container
COPY package*.json ./

# Install any needed packages specified in package.json
RUN npm install

# Copy the rest of the application source code from the host to the container
COPY . .

# Build the Next.js application
RUN npm run build

# Make port 3000 available to the world outside this container
EXPOSE 3000

# Run the application
CMD ["node", "server.js"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with the official Node.js image as the base image. This provides a consistent environment for building the application.

2. **Working Directory**: The `WORKDIR` instruction sets the directory where the application will be installed and run.

3. **Dependencies**: The `COPY package*.json .` command copies the `package.json` and `package-lock.json` files from the host machine to the container. The `RUN npm install` command then installs all the dependencies specified in these files.

4. **Application Source**: The `COPY . .` command copies the rest of the application source code from the host machine to the container.

5. **Build**: The `RUN npm run build` command builds the Next.js application using the default build command. This step is crucial as it optimizes the application for production.

6. **Port Exposure**: The `EXPOSE 3000` instruction informs Docker that the application listens on port 3000, which is the default port for Next.js applications.

7. **Command**: The `CMD ["node", "server.js"]` command specifies the command to run when the container starts. This is typically the entry point for a Next.js application, which is a Node.js server that runs the application.

This Dockerfile assumes that you have a `server.js` file in your project, which is the entry point for your application. Make sure to adjust the paths and commands if your application's structure is different.
