Certainly! Below is a basic Dockerfile for a server-rendered web application built in Node.js using Next.js. This Dockerfile assumes you have a Next.js project set up with a `package.json` and a `next.config.js` file in the root directory of your project.

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14-slim

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy package.json and package-lock.json to the working directory
COPY package*.json ./

# Install dependencies
RUN npm install

# Copy the rest of the application code to the working directory
COPY . .

# Build the application
RUN npm run build

# Expose the port Next.js runs on
EXPOSE 3000

# Command to run the application
CMD ["node", "server.js"]
```

### Explanation:

1. **FROM node:14-slim**: This line specifies the base image for the Docker container. It uses the official Node.js image with version 14 and is optimized for size.

2. **WORKDIR /usr/src/app**: Sets the working directory in the container to `/usr/src/app`. This is where your application code will be stored.

3. **COPY package*.json ./**: Copies the `package.json` and `package-lock.json` files from your local machine to the working directory inside the container.

4. **RUN npm install**: Installs all the dependencies listed in your `package.json` file.

5. **COPY . .**: Copies all the files from your local machine to the working directory inside the container, including your Next.js project code.

6. **RUN npm run build**: Builds your Next.js application. This step is optional if your application is already built and you only want to run it.

7. **EXPOSE 3000**: Tells Docker that the application will be running on port 3000, which is the default port Next.js uses for server-side rendering.

8. **CMD ["node", "server.js"]**: Defines the default command to run the application. The `server.js` file is typically the entry point for Next.js applications.

### Notes:

- Replace `14-slim` with a more specific version of Node.js if needed.
- Ensure that your application has a `server.js` file that points to the correct entry point.
- If you need to serve static files, you may need to add additional steps to copy static files to the correct location in the container.
