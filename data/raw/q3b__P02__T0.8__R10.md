Certainly! Below is a Dockerfile for a server-rendered web application built in Node.js using Next.js:

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:16

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy package.json and package-lock.json to the container
COPY package*.json ./

# Install any needed packages specified in package.json
RUN npm install

# Copy the rest of the application code into the container
COPY . .

# Build the application
RUN npm run build

# Expose the default port for Next.js
EXPOSE 3000

# Start the application
CMD ["npm", "start"]
```

### Explanation:
- **FROM node:16**: Uses the latest version of Node.js (16) as the base image.
- **WORKDIR /usr/src/app**: Sets the working directory for the application inside the container.
- **COPY package*.json ./**: Copies the `package.json` and `package-lock.json` files into the container.
- **RUN npm install**: Installs all dependencies specified in `package.json`.
- **COPY . .**: Copies the rest of the application code into the container.
- **RUN npm run build**: Builds the Next.js application.
- **EXPOSE 3000**: Exposes port 3000, which is the default port for Next.js.
- **CMD ["npm", "start"]**: Specifies the command to run when the container starts, which is `npm start` to start the Next.js server.

To build and run this Docker image, you would typically use the following commands:

```sh
docker build -t nextjs-app .
docker run -p 3000:3000 nextjs-app
```

This will build the Docker image and run the application, exposing it on port 3000.
