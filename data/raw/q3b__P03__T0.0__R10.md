Certainly! Below is a Dockerfile for a background worker built in Node.js using BullMQ. This Dockerfile assumes you have a basic Node.js application set up with BullMQ for handling background tasks.

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy package.json and package-lock.json to the container at /usr/src/app
COPY package*.json ./

# Install any needed packages specified in package.json
RUN npm install

# Copy the rest of your application code to the container
COPY . .

# Expose the port your application runs on
EXPOSE 3000

# Start the application
CMD ["node", "app.js"]
```

### Explanation:

1. **Base Image**: The `node:14` image is used as the base image, which includes Node.js and npm.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory for the application inside the container.

3. **Copy Dependencies**: The `COPY package*.json .` command copies the `package.json` and `package-lock.json` files into the container. The `.` at the end specifies the current directory on the host machine.

4. **Install Dependencies**: The `RUN npm install` command installs all the dependencies listed in `package.json`.

5. **Copy Application Code**: The `COPY . .` command copies the rest of your application code into the container.

6. **Expose Port**: The `EXPOSE 3000` instruction informs Docker that the application listens on port 3000.

7. **Start Application**: The `CMD ["node", "app.js"]` command specifies the command to run when the container starts, which is to execute the `app.js` file.

### Note:
- Ensure that your `app.js` file is correctly configured to use BullMQ for handling background tasks.
- You may need to adjust the `package.json` and `app.js` files to fit your specific application requirements.
- If you have any additional configuration or environment variables, you can add them to the `CMD` or `ENV` instructions as needed.
