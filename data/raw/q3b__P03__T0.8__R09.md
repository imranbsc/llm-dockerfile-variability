Certainly! Below is a simple Dockerfile for a background worker built in Node.js using BullMQ.

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy package.json and package-lock.json files to the container
COPY package*.json ./

# Install dependencies
RUN npm install

# Copy the rest of the application code
COPY . .

# Expose the port used by BullMQ
EXPOSE 6379

# Start the application
CMD ["node", "app.js"]
```

### Explanation:

1. **Parent Image**: The base image is `node:14`, which is a popular and widely used Node.js runtime environment.

2. **Working Directory**: The `WORKDIR` directive sets the working directory in the container to `/usr/src/app`.

3. **Copying Files**:
   - `COPY package*.json ./` copies the `package.json` and `package-lock.json` files into the container.
   - `COPY . .` copies the rest of the application code into the container.

4. **Installing Dependencies**: The `npm install` command installs all the dependencies listed in `package.json`.

5. **Exposing a Port**: The `EXPOSE` directive specifies that the container listens on port 6379, which is commonly used by BullMQ for Redis.

6. **Running the Application**: The `CMD` directive specifies the command to run the application, which is `node app.js`.

### Steps to Build and Run the Docker Container:

1. **Build the Docker Image**:
   ```bash
   docker build -t my-bullmq-worker .
   ```

2. **Run the Docker Container**:
   ```bash
   docker run -d --name my-bullmq-container my-bullmq-worker
   ```

Make sure to replace `app.js` with the entry point of your worker application.
