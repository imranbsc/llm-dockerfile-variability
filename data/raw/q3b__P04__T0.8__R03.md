Certainly! Below is a Dockerfile for a Node.js command-line tool that uses Commander.js. This Dockerfile assumes you have a `package.json` file in your project directory.

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in package.json
RUN npm install

# Make port 3000 available to the world outside this container
EXPOSE 3000

# Define environment variable
ENV NAME World

# Run app.js when the container launches
CMD ["node", "app.js"]
```

### Explanation:

1. **Base Image**: The `FROM node:14-slim` line specifies that the container will use the official Node.js 14 image with a slim version, which is smaller and more efficient for production use.

2. **Working Directory**: The `WORKDIR /app` sets the default directory for the application within the container.

3. **Copy Files**: The `COPY . /app` command copies all files from the current directory (host) to the `/app` directory inside the container.

4. **Install Dependencies**: The `RUN npm install` command installs all dependencies listed in your `package.json`.

5. **Expose Port**: The `EXPOSE 3000` line informs Docker that the application will listen on port 3000, which is where you should run the application.

6. **Environment Variable**: The `ENV NAME World` line sets an environment variable for your application.

7. **Command**: The `CMD ["node", "app.js"]` line specifies the command to run when the container starts. This is where your application will be executed.

### Building and Running the Docker Image

1. **Build the Docker Image**:
   ```sh
   docker build -t my-node-app .
   ```

2. **Run the Docker Container**:
   ```sh
   docker run -p 3000:3000 my-node-app
   ```

This setup will create a Docker container that runs your Node.js application using Commander.js, and it will expose the application on port 3000.
