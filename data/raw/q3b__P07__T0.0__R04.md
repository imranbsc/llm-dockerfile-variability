Certainly! Below is a Dockerfile for a server-rendered web application built in Python using Django. This Dockerfile assumes you have a Django project set up and ready to run.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 8000 available to the world outside this container
EXPOSE 8000

# Run app.py when the container launches
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]
```

### Explanation:

1. **Base Image**: The `python:3.9-slim` image is used as the base image, which is a lightweight version of Python 3.9 with a small footprint.

2. **Working Directory**: The `WORKDIR /app` sets the working directory inside the container to `/app`, where your Django project will be located.

3. **Copy Files**: The `COPY . /app` command copies all files from the current directory to the `/app` directory inside the container.

4. **Install Dependencies**: The `RUN pip install --no-cache-dir -r requirements.txt` command installs all the dependencies listed in your `requirements.txt` file. The `--no-cache-dir` flag ensures that the cache is not used, which can be useful for debugging.

5. **Expose Port**: The `EXPOSE 8000` command makes port 8000 available to the world outside this container. This is necessary for the Django development server to listen on this port.

6. **Run Command**: The `CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]` command runs the Django development server, making it accessible from any machine on the network that can reach the container.

### Notes:

- Ensure that your `requirements.txt` file is correctly formatted and contains all the necessary dependencies for your Django project.
- If you have any additional setup steps or environment variables, you can add them after the `CMD` line.
- This Dockerfile is for development purposes. For production, consider using a more robust setup with a production-ready web server like Gunicorn and a database like PostgreSQL or MySQL.
