Certainly! Below is a Dockerfile for a server-rendered web application built in Python using Django.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 80 available to the world outside this container
EXPOSE 80

# Define environment variable
ENV NAME World

# Run app.py when the container launches
CMD ["python", "manage.py", "runserver", "0.0.0.0:80"]
```

### Key Points:
- **Python 3.9-slim**: This image is smaller than the full `python` image and is optimized for performance.
- **WORKDIR /app**: This sets the working directory for subsequent commands.
- **COPY . /app**: Copies the current directory contents into the container at `/app`.
- **pip install --no-cache-dir -r requirements.txt**: Installs the Python dependencies listed in `requirements.txt` without caching to ensure the latest versions are used.
- **EXPOSE 80**: This makes port 80 available to other containers.
- **ENV NAME World**: Sets an environment variable.
- **CMD ["python", "manage.py", "runserver", "0.0.0.0:80"]**: Specifies the command to run when the container starts, which is the Django development server.

Make sure to replace `requirements.txt` with the actual list of dependencies for your Django project.
