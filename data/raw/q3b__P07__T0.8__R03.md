Certainly! Below is a Dockerfile for a server-rendered web application built in Python using Django. This Dockerfile assumes you are using a PostgreSQL database for the application.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 8000 available to the world outside this container
EXPOSE 8000

# Run the web service on container startup
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]
```

### Explanation:

1. **Base Image**: The `python:3.9-slim` image is used as the base image, which is a smaller and more optimized version of the standard Python image.

2. **Working Directory**: The `WORKDIR /app` sets the working directory for the application within the container.

3. **Copy Files**: The `COPY . /app` command copies the current directory contents into the container at `/app`. This is where your Django application files will be stored.

4. **Install Dependencies**: The `RUN pip install --no-cache-dir -r requirements.txt` command installs all the dependencies specified in your `requirements.txt` file. The `--no-cache-dir` flag ensures that the package cache is not used, which can help reduce the size of the final image.

5. **Expose Port**: The `EXPOSE 8000` command makes port 8000 available to the world outside this container. This is important for the Django development server to listen on this port.

6. **Command**: The `CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]` command specifies the command to run when the container starts. This command runs the Django development server, which listens on all network interfaces (0.0.0.0) and port 8000.

### Additional Notes:

- Make sure your `requirements.txt` file is included in the same directory as your `Dockerfile`.
- If you are using a different database, you may need to install the appropriate database adapter and configure it in your Django settings.
- Consider adding environment variables or configuration files to customize your Django application within the container.
