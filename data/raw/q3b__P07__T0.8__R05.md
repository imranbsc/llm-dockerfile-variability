Certainly! Below is a Dockerfile for a server-rendered web application built in Python using Django. This Dockerfile sets up a Django development environment within a container.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 8000 available to the world outside this container
EXPOSE 8000

# Run app.py when the container launches
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]
```

### Explanation:
- **FROM python:3.9-slim**: This line specifies the base image for the Docker container. The `3.9-slim` version is a lightweight version of the Python 3.9 runtime.
- **WORKDIR /app**: This sets the working directory in the container to `/app`, where your project files will be stored.
- **COPY . /app**: This copies all the files from the local directory to the `/app` directory in the container.
- **RUN pip install --no-cache-dir -r requirements.txt**: This installs the Python packages listed in the `requirements.txt` file. The `--no-cache-dir` option ensures that the package cache is not used, which can be useful for development.
- **EXPOSE 8000**: This line makes port 8000 available to the world outside the container.
- **CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]**: This sets the default command to run when the container starts, which is to start the Django development server on all interfaces (0.0.0.0) at port 8000.
