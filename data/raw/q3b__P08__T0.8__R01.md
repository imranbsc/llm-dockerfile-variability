Here is a simple Dockerfile for a Python-based background worker using Celery. This Dockerfile assumes you are using a PostgreSQL database as the backend for Celery.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.8-slim-buster

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy the current directory contents into the container at /usr/src/app
COPY . .

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 5672 available to the world outside this container
EXPOSE 5672

# Define environment variable
ENV CELERY_BROKER_URL=redis://redis:6379/0

# Define environment variable
ENV CELERY_RESULT_BACKEND=postgresql://user:password@db:5432/celerydb

# Define environment variable
ENV CELERY_BEAT_SCHEDULE_FILENAME=/usr/src/app/celery_beat_schedule.json

# Set the default command to run the Celery worker
CMD ["celery", "worker", "-A", "worker_app", "--loglevel=info"]
```

In this Dockerfile:
- The Python runtime is used as a parent image.
- The working directory is set to `/usr/src/app`.
- The contents of the current directory are copied into the container.
- Dependencies specified in `requirements.txt` are installed.
- The Redis broker URL is set to `redis://redis:6379/0`.
- The PostgreSQL result backend URL is set to `postgresql://user:password@db:5432/celerydb`.
- The Celery beat schedule file path is set.
- The default command to run the Celery worker is specified, which is to run the worker with the application name `worker_app` and log level set to `info`.

Make sure to replace `redis`, `db`, `user`, `password`, and `celerydb` with your actual Redis host, database host, PostgreSQL username, password, and database name.
