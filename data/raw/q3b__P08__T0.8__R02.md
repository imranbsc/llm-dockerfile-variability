Certainly! Below is a Dockerfile for a background worker built in Python using Celery. This Dockerfile assumes you have a Python application set up with Celery configured to run as a background worker.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.8-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 5672 available to the world outside this container
EXPOSE 5672

# Define environment variable
ENV CELERY_BROKER_URL=redis://redis:6379/0

# Run the command to start the Celery worker
CMD ["celery", "worker", "--app=your_app_name", "--loglevel=info"]
```

### Explanation:

1. **Base Image**: The `python:3.8-slim` image is used as the base, which is a smaller and more efficient version of the Python image.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory to `/app` where the application files will be placed.

3. **Copy Files**: The `COPY` instruction copies all files from the current directory to the `/app` directory inside the container.

4. **Install Dependencies**: The `RUN` instruction installs the necessary Python packages listed in `requirements.txt`. The `--no-cache-dir` option is used to speed up the installation process by avoiding caching unnecessary files.

5. **Expose Port**: The `EXPOSE` instruction makes port 5672 available to the world outside this container, which is the default port for RabbitMQ, the message broker used by Celery.

6. **Environment Variable**: The `ENV` instruction sets the `CELERY_BROKER_URL` to point to a Redis broker running on the host at `redis:6379/0`.

7. **Run Celery Worker**: The `CMD` instruction starts the Celery worker, specifying the application name (`your_app_name`) and log level.

### Note:
- Replace `your_app_name` with the actual name of your Celery application module.
- Ensure that Redis is running and accessible from the container as specified in the `CELERY_BROKER_URL`.
- Make sure `requirements.txt` is in the same directory as your Dockerfile.
