Certainly! Below is a Dockerfile for a background worker built in Python using Celery. This Dockerfile assumes you have a Python application with Celery set up, and it includes basic dependencies and configurations.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy the current directory contents into the container at /usr/src/app
COPY . .

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Install Celery
RUN pip install celery

# Create the Celery beat schedule
RUN mkdir /usr/src/app/beat_schedule

# Define environment variables for Celery (e.g., broker URL)
ENV CELERY_BROKER_URL=redis://localhost:6379/0

# Define environment variables for Celery beat (e.g., schedule filename)
ENV CELERY_BEAT_SCHEDULE=beat_schedule.yml

# Expose the default Celery port
EXPOSE 5672

# Run the Celery worker
CMD ["celery", "worker", "--loglevel=info"]
```

### Explanation:

- **FROM python:3.9-slim**: This line specifies the base image as Python 3.9 with a slim version.
- **WORKDIR /usr/src/app**: Sets the working directory for the application.
- **COPY . .**: Copies the current directory contents into the container.
- **RUN pip install --no-cache-dir -r requirements.txt**: Installs the Python dependencies listed in `requirements.txt`.
- **RUN pip install celery**: Installs Celery in the container.
- **RUN mkdir /usr/src/app/beat_schedule**: Creates a directory to store the Celery beat schedule.
- **ENV CELERY_BROKER_URL=redis://localhost:6379/0**: Sets the broker URL for Celery.
- **ENV CELERY_BEAT_SCHEDULE=beat_schedule.yml**: Sets the schedule filename for Celery beat.
- **EXPOSE 5672**: Exposes the default port used by Celery.
- **CMD ["celery", "worker", "--loglevel=info"]**: Runs the Celery worker with an info log level.

Make sure to have a `requirements.txt` file in your project directory with the necessary dependencies, and a `beat_schedule.yml` file to define your Celery tasks and schedules. Adjust the environment variables and paths as needed for your specific setup.
