Certainly! Below is a Dockerfile for a background worker built in Python using Celery. This Dockerfile assumes you are using a standard Python environment, such as `python:3.9-slim`.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 5672 available to the world outside this container
EXPOSE 5672

# Define environment variable
ENV CELERY_BROKER_URL=pyamqp://guest:guest@rabbitmq:5672//

# Run app.py when the container launches
CMD ["celery", "-A", "worker", "worker", "--loglevel=info"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with an official Python image, which is very lightweight and efficient for running Python applications.

2. **Working Directory**: The working directory within the container is set to `/app`. This is where your application's files will be located.

3. **Copy Files**: The `COPY . /app` command copies all files from the current directory to the `/app` directory inside the container.

4. **Install Dependencies**: The `RUN pip install --no-cache-dir -r requirements.txt` command installs all dependencies listed in your `requirements.txt` file. The `--no-cache-dir` flag ensures that the package cache is not used, which is useful for reproducibility.

5. **Expose Port**: The `EXPOSE 5672` command makes port 5672 available to the world outside this container. This is necessary for Celery to communicate with RabbitMQ.

6. **Environment Variable**: The `ENV CELERY_BROKER_URL=pyamqp://guest:guest@rabbitmq:5672//` sets the environment variable for Celery's broker URL. This tells Celery to connect to RabbitMQ, which is a message broker used by Celery for task scheduling.

7. **CMD**: The `CMD ["celery", "-A", "worker", "worker", "--loglevel=info"]` command starts the Celery worker in the `worker` app, using the default broker URL, and sets the log level to `info`.

Make sure you have `requirements.txt` in your project directory, which lists all the dependencies needed for your application. If you use Docker Compose, you will also need a `docker-compose.yml` file to define the RabbitMQ service and link it to the worker container.
