Certainly! Below is a Dockerfile for a background worker built in Python using Celery. This Dockerfile assumes you have a Python script that sets up a Celery worker.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 5672 available to the world outside this container
EXPOSE 5672

# Define environment variable
ENV CELERY_BROKER_URL=pyamqp://guest@rabbitmq:5672//

# Run app.py when the container launches
CMD ["celery", "worker", "-A", "myproject.tasks", "--loglevel=info"]
```

### Explanation:
- **Base Image**: The `python:3.9-slim` image is used as the base image, which is a lightweight version of Python.
- **Working Directory**: The `WORKDIR` directive sets the directory in the container where the application will be run.
- **Copy Files**: The `COPY` command copies the contents of the current directory to the `/app` directory in the container.
- **Install Dependencies**: The `pip install` command installs the necessary dependencies from `requirements.txt`.
- **Expose Port**: The `EXPOSE` directive allows the container to expose port 5672, which is used by RabbitMQ.
- **Environment Variable**: The `ENV` directive sets the `CELERY_BROKER_URL` environment variable, which is used by Celery to connect to the RabbitMQ broker.
- **Run Command**: The `CMD` directive specifies the command to run when the container starts, which is to start a Celery worker process with the specified app and log level.

### Additional Notes:
- Ensure you have a `requirements.txt` file in your project directory listing all the dependencies needed for your application.
- You should also have a `myproject/tasks.py` file where your Celery tasks are defined.
- Make sure you have a RabbitMQ instance running and accessible at `rabbitmq:5672` for the Celery worker to connect to.
