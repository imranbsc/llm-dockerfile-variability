Certainly! Below is a simple Dockerfile for a command-line tool built in Python using Click. This Dockerfile assumes you have a Python script named `app.py` that uses Click to define your command-line interface.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 80 available to the world outside this container
EXPOSE 80

# Define environment variable
ENV NAME World

# Run app.py when the container launches
CMD ["python", "app.py"]
```

### Explanation:

1. **Base Image**: The `python:3.9-slim` image is used as the base image, which is a lightweight version of Python 3.9.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app`.

3. **Copy Files**: The `COPY` instruction copies the current directory contents into the container at `/app`.

4. **Install Dependencies**: The `RUN` instruction installs the dependencies listed in `requirements.txt` using `pip`. The `--no-cache-dir` flag is used to avoid caching dependencies, which can be useful for development.

5. **Expose Port**: The `EXPOSE` instruction makes port 80 available to the world outside this container.

6. **Environment Variable**: The `ENV` instruction sets the `NAME` environment variable to `World`.

7. **Command to Run**: The `CMD` instruction specifies the command to run when the container starts, which is `python app.py`.

### Note:
- Ensure you have a `requirements.txt` file in your project directory listing all the Python packages your application depends on.
- Replace `app.py` with the actual name of your Python script if it's different.
- Adjust the Python version and other settings as needed for your specific use case.
