Certainly! Below is a simple Dockerfile for a command-line tool built in Python using the Click library. This Dockerfile sets up a Python environment, installs the necessary dependencies, and then copies the application code into the container.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 80 available to the world outside this container
EXPOSE 80

# Define environment variable
ENV NAME World

# Run app.py when the container launches
CMD ["python", "app.py"]
```

### Explanation:

- **FROM python:3.9-slim**: This line specifies the base image to use. The `slim` variant is used to make the image smaller.
- **WORKDIR /app**: Sets the working directory inside the container where the application will be located.
- **COPY . /app**: Copies all files from the current directory to the `/app` directory in the container.
- **RUN pip install --no-cache-dir -r requirements.txt**: Installs the Python dependencies listed in the `requirements.txt` file. The `--no-cache-dir` flag avoids using a cache directory for faster installation.
- **EXPOSE 80**: This line tells Docker that the container will listen on port 80, which is typically used for HTTP services.
- **ENV NAME World**: Sets an environment variable named `NAME` with the value `World`. You can change this to any desired default value.
- **CMD ["python", "app.py"]**: Specifies the command to run when the container starts. In this case, it runs the `app.py` script using Python.

### Additional Notes:

- Ensure you have a `requirements.txt` file in your project directory listing all the Python packages required by your application.
- Make sure your application code is in a file named `app.py` or specify the correct entry point in the `CMD` instruction if it's different.
- If you need to expose more ports or install additional system packages, you can add more lines to the Dockerfile accordingly.
