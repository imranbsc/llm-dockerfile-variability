Certainly! Below is a Dockerfile for a scheduled batch job built in Python using APScheduler. This Dockerfile assumes you have a Python script that uses APScheduler to schedule tasks.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 5000 available to the world outside this container
EXPOSE 5000

# Define environment variable
ENV NAME World

# Run app.py when the container launches
CMD ["python", "app.py"]
```

### Explanation:

1. **Base Image**: The `python:3.9-slim` image is used as the base image, which is a lightweight version of Python 3.9.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app`.

3. **Copy Files**: The `COPY` instruction copies the current directory contents into the container at `/app`.

4. **Install Dependencies**: The `RUN` instruction installs the necessary packages specified in `requirements.txt` using `pip`. The `--no-cache-dir` flag is used to avoid caching dependencies, which can be useful for development.

5. **Expose Port**: The `EXPOSE` instruction makes port 5000 available to the world outside this container.

6. **Environment Variable**: The `ENV` instruction sets the environment variable `NAME` to `World`.

7. **Command to Run**: The `CMD` instruction specifies the command to run when the container starts, which is `python app.py`.

### Additional Notes:

- Ensure you have a `requirements.txt` file in your project directory that lists all the Python packages your application depends on.
- Replace `app.py` with the name of your Python script that uses APScheduler.
- You may need to adjust the Python version and other dependencies based on your specific requirements.
