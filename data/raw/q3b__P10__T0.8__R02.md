Certainly! Below is a Dockerfile that builds a scheduled batch job using Python and APScheduler. This Dockerfile assumes you have a Python script that uses APScheduler to run scheduled tasks.

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.8-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 5000 available to the world outside this container
EXPOSE 5000

# Define environment variable
ENV NAME World

# Run app.py when the container launches
CMD ["python", "app.py"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with a Python 3.8 slim image, which is a lightweight version of Python.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app`.

3. **Copy Files**: The `COPY` instruction copies the current directory contents into the container at `/app`.

4. **Install Dependencies**: The `RUN` instruction uses `pip` to install the dependencies listed in `requirements.txt` without caching the installed packages.

5. **Expose Port**: The `EXPOSE` instruction informs Docker that the container listens on port 5000.

6. **Environment Variable**: The `ENV` instruction sets an environment variable `NAME` to `World`.

7. **Command to Run**: The `CMD` instruction specifies the command to run when the container starts, which in this case is to execute `python app.py`.

### Note:
- Ensure you have a `requirements.txt` file in your project directory that lists all the Python packages your application depends on.
- Replace `app.py` with the name of your Python script that uses APScheduler to schedule tasks.
- If you have any additional setup or configurations, you can add them as needed within the `Dockerfile`.
