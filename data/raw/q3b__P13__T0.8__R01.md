Here's a simple Dockerfile for a background worker built in Java using Spring Boot and RabbitMQ. This Dockerfile assumes that you have a Spring Boot application with RabbitMQ integration.

```Dockerfile
# Use an official OpenJDK runtime as a parent image
FROM openjdk:17-jdk-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Make port 8080 available to the world outside this container
EXPOSE 8080

# Make port 5672 available to the world outside this container for RabbitMQ
EXPOSE 5672

# Define environment variable
ENV SPRING_PROFILES_ACTIVE=worker

# Add RabbitMQ connection properties if needed
ENV RABBITMQ_URL=amqp://guest:guest@rabbitmq:5672/

# Run the application using the Spring Boot executable
ENTRYPOINT ["java", "-jar", "target/your-application.jar"]
```

### Explanation:
- **Base Image**: The image `openjdk:17-jdk-slim` is used as the base image, which is a lightweight version of OpenJDK.
- **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app`.
- **Copy Files**: The `COPY` instruction copies the contents of the current directory to the `/app` directory in the container.
- **Expose Ports**: The `EXPOSE` instructions make ports 8080 and 5672 available to other containers, which are the default ports for Spring Boot and RabbitMQ, respectively.
- **Environment Variable**: The `ENV` instruction sets the `SPRING_PROFILES_ACTIVE` environment variable to `worker`, which specifies the profile for the worker application.
- **RabbitMQ URL**: The `RABBITMQ_URL` environment variable is set to the default RabbitMQ URL, but you can modify it to point to your RabbitMQ instance if necessary.
- **Run Command**: The `ENTRYPOINT` command specifies the command to run the application, which is the Spring Boot executable located in the `target` directory.

### Building the Docker Image:
To build this Docker image, navigate to the directory containing the Dockerfile and run:

```sh
docker build -t your-worker-image-name .
```

Replace `your-worker-image-name` with the desired name for your Docker image.
