Certainly! Below is a Dockerfile for a background worker built in Java using Spring Boot and RabbitMQ. This Dockerfile will set up a Java application that listens for messages from a RabbitMQ queue and processes them.

```Dockerfile
# Use an official OpenJDK runtime as a parent image
FROM openjdk:17-jdk-slim

# Set the working directory in the container
WORKDIR /app

# Copy the local code to the container at /app
COPY target/your-application-name.jar /app/your-application-name.jar

# Make port 8080 available to the world outside this container
EXPOSE 8080

# Define environment variable
ENV RABBITMQ_URI amqp://guest:guest@rabbitmq:5672/

# Run the application
ENTRYPOINT ["java", "-jar", "your-application-name.jar"]
```

### Explanation:
- **Base Image**: `openjdk:17-jdk-slim` is used as the base image, which is a lightweight version of OpenJDK with a smaller footprint.
- **Working Directory**: `WORKDIR /app` sets the working directory to `/app` inside the container.
- **Copy Application**: `COPY target/your-application-name.jar /app/your-application-name.jar` copies the compiled JAR file into the container.
- **Expose Port**: `EXPOSE 8080` makes port 8080 available to the host machine.
- **Environment Variable**: `ENV RABBITMQ_URI amqp://guest:guest@rabbitmq:5672/` sets the environment variable `RABBITMQ_URI` to connect to a RabbitMQ instance running on the host machine. You can modify this to connect to a different RabbitMQ server if needed.
- **Entrypoint**: `ENTRYPOINT ["java", "-jar", "your-application-name.jar"]` starts the application when the container is run.

### Building and Running the Docker Image:
1. Build the Docker image by running:
   ```bash
   docker build -t your-image-name .
   ```
2. Run the Docker container by running:
   ```bash
   docker run -d --name your-container-name -e RABBITMQ_URI=amqp://guest:guest@rabbitmq:5672/ your-image-name
   ```

Make sure you have RabbitMQ running on your host machine or provide the correct connection details if it's running on a different server.
