Certainly! Below is a Dockerfile for a scheduled batch job built in Java using Spring Batch. This Dockerfile assumes you have a basic Java Spring Batch application set up.

```Dockerfile
# Use an official OpenJDK runtime as a parent image
FROM openjdk:17-jdk-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Make port 8080 available to the world outside this container
EXPOSE 8080

# Run the application
CMD ["java", "-jar", "target/spring-batch-job-1.0-SNAPSHOT.jar"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with an official OpenJDK runtime image (`openjdk:17-jdk-slim`). This is a lightweight version of OpenJDK that is optimized for size and performance.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app`. This is the directory where your application will be deployed.

3. **Copy Files**: The `COPY` instruction copies all files from the current directory to the `/app` directory in the container. This includes your source code, build artifacts, and any other necessary files.

4. **Expose Port**: The `EXPOSE` instruction specifies that the application is listening on port 8080. This is useful for Docker to route traffic to the correct container port.

5. **Run Command**: The `CMD` instruction specifies the command to run when the container starts. In this case, it runs the Spring Boot application using the JAR file located in the `target` directory.

To build and run this Docker image, you would typically use the following commands:

```sh
# Build the Docker image
docker build -t spring-batch-job .

# Run the Docker container
docker run -p 8080:8080 spring-batch-job
```
