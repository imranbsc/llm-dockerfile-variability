Certainly! Below is a Dockerfile for a scheduled batch job built in Java using Spring Batch. This Dockerfile assumes you are using a Java 17 environment.

```Dockerfile
# Use an official OpenJDK runtime as a parent image
FROM openjdk:17-jdk-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Make port 8080 available to the world outside this container
EXPOSE 8080

# Make port 8081 available to the world outside this container
EXPOSE 8081

# Define environment variable
ENV SPRING_APPLICATION_JSON '{"server":{"port":8080},"batch":{"job":{"names":{"exampleJob":"exampleJob"}}}}'

# Run the application using the specified command
CMD ["java", "-jar", "target/example-batch-job-0.0.1-SNAPSHOT.jar"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with an official OpenJDK 17 image, which is a lightweight, secure, and reliable base image for running Java applications.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory in the container to `/app`. This is where the application's files will be placed.

3. **Copy Files**: The `COPY` instruction copies the current directory contents into the container at the `/app` directory. This includes your Spring Batch application's source code and any necessary configuration files.

4. **Expose Ports**: The `EXPOSE` instructions specify that the container listens on ports 8080 and 8081, which are commonly used for HTTP and HTTPS, respectively.

5. **Environment Variable**: The `ENV` instruction sets an environment variable `SPRING_APPLICATION_JSON`. This variable is used to configure the application's properties, including the HTTP port and the job name.

6. **Command to Run**: The `CMD` instruction specifies the command to run the application using the `java` command. The `-jar` option is used to specify the JAR file to run.

### Notes:

- Replace `example-batch-job-0.0.1-SNAPSHOT.jar` with the actual JAR file name of your Spring Batch application.
- Ensure that the application has all the necessary dependencies in the `pom.xml` or `build.gradle` file and that they are included in the build process.
- You may need to adjust the environment variables and ports based on your specific application configuration.
