Certainly! Below is a Dockerfile for a REST API built in Go using the Gin web framework.

```Dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.19 as build-env

# Set the working directory in the container
WORKDIR /go/src/app

# Copy the current directory contents into the container at /go/src/app
COPY . /go/src/app

# Install any needed packages specified in requirements.txt
RUN go get -d -v ./...

# Build the Go application
RUN go build -o app

# Use an official lightweight base image
FROM alpine:latest

# Set the working directory in the container
WORKDIR /app

# Copy the binary from the build-env to the new image
COPY --from=build-env /go/src/app/app /app/app

# Make port 80 available to the world outside this container
EXPOSE 80

# Run the app
CMD ["./app"]
```

### Explanation:
- **`FROM golang:1.19 as build-env`**: This line specifies the base image as the official Go 1.19 image, tagged as `build-env`.
- **`WORKDIR /go/src/app`**: Sets the working directory to `/go/src/app` inside the container.
- **`COPY . /go/src/app`**: Copies the current directory contents into the container at the `/go/src/app` directory.
- **`RUN go get -d -v ./...`**: Installs any dependencies specified in the `go.mod` and `go.sum` files.
- **`RUN go build -o app`**: Builds the Go application and outputs it as an executable named `app`.
- **`FROM alpine:latest`**: Uses the Alpine Linux image as a base image for the final container.
- **`WORKDIR /app`**: Sets the working directory to `/app` inside the new image.
- **`COPY --from=build-env /go/src/app/app /app/app`**: Copies the built application binary from the `build-env` image to the new image.
- **`EXPOSE 80`**: Exposes port 80, which is the default HTTP port for a web server.
- **`CMD ["./app"]`**: Specifies the default command to run when the container starts, which is the entrypoint for the application.
