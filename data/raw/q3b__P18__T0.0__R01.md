```Dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.17-alpine as builder

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN go mod download

# Build the Go application
RUN go build -o asynq-worker

# Use an official Alpine image as a parent image for the final image
FROM alpine:3.14

# Set the working directory in the container
WORKDIR /app

# Copy the binary from the builder stage
COPY --from=builder /app/asynq-worker .

# Expose the port the application listens on
EXPOSE 8080

# Run the application
CMD ["./asynq-worker"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with an official Go runtime image (`golang:1.17-alpine`) as the base image. This image is lightweight and includes the Go toolchain.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app`, which is where the application code will be placed.

3. **Copy Application Code**: The `COPY` instruction copies the current directory contents into the container at `/app`. This includes your Go application code and any necessary configuration files.

4. **Install Dependencies**: The `RUN go mod download` command installs the dependencies specified in your `go.mod` file.

5. **Build the Application**: The `RUN go build -o asynq-worker` command builds the Go application and outputs it as a binary named `asynq-worker`.

6. **Final Image**: The Dockerfile uses an official Alpine image as the base image for the final image. This image is smaller and more efficient than the Go runtime image.

7. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app` again.

8. **Copy Binary**: The `COPY --from=builder /app/asynq-worker .` command copies the binary from the builder stage into the final image.

9. **Expose Port**: The `EXPOSE 8080` instruction tells Docker that the application listens on port 8080.

10. **Run the Application**: The `CMD ["./asynq-worker"]` instruction specifies the command to run the application when the container starts.
