Here's a simple Dockerfile for a Go-based background worker using Asynq:

```dockerfile
# Use an official Golang runtime as a parent image
FROM golang:1.16-alpine

# Set the working directory in the container
WORKDIR /app

# Copy the Go application source code into the container
COPY . /app

# Install any needed packages specified in requirements.txt
RUN apk update && apk add --no-cache \
    git \
    make \
    && go mod download

# Build the Go application
RUN CGO_ENABLED=0 go build -o asynq_worker cmd/asynq_worker/main.go

# Expose the port the application runs on
EXPOSE 6379

# Run the application when the container launches
CMD ["/app/asynq_worker"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with an official Go 1.16 Alpine image, which is lightweight and optimized for running Go applications.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container where the application source code will be placed.

3. **Copy Source Code**: The `COPY` instruction copies the entire contents of the current directory to the `/app` directory inside the container.

4. **Install Dependencies**: The `apk update && apk add --no-cache` command installs Git and `make`, which are used for fetching dependencies and building the application. `go mod download` downloads the Go module dependencies specified in `go.mod`.

5. **Build the Application**: The `go build` command compiles the Go application into an executable named `asynq_worker`.

6. **Expose Port**: The `EXPOSE` instruction specifies that the application is listening on port 6379, which is the default port for Redis.

7. **Run the Application**: The `CMD` instruction specifies the command to run when the container starts, which is the compiled `asynq_worker` binary.

This Dockerfile provides a basic setup for a Go-based background worker using Asynq, including building and running the application inside a Docker container.
