Certainly! Below is a Dockerfile for a background worker built in Go using Asynq. This Dockerfile assumes you have a Go project set up with Asynq as a dependency.

```Dockerfile
# Use a Go base image
FROM golang:1.19 AS builder

# Set the working directory in the container
WORKDIR /app

# Copy the Go source files into the container
COPY . .

# Build the Go application
RUN CGO_ENABLED=0 go build -o asynq_worker

# Use an alpine image as the final image
FROM alpine:latest

# Set the working directory in the container
WORKDIR /app

# Copy the built binary from the builder stage
COPY --from=builder /app/asynq_worker .

# Expose the port on which Asynq runs
EXPOSE 6379

# Run the Asynq worker
CMD ["./asynq_worker"]
```

### Explanation:
- **Base Image**: The `golang:1.19` image is used to build the Go application. You can choose another Go version if needed.
- **Working Directory**: The `WORKDIR` directive sets the directory where the build process will start.
- **Copy Source Files**: The `COPY . .` command copies all files from the host into the container's working directory.
- **Build the Application**: The `RUN CGO_ENABLED=0 go build -o asynq_worker` command builds the Go application into an executable named `asynq_worker`.
- **Final Image**: The `alpine:latest` image is used as the final base image. This image is lightweight and optimized for running Go applications.
- **Working Directory**: Similar to the builder stage, the `WORKDIR` directive sets the directory for the final application.
- **Copy Built Binary**: The `COPY --from=builder /app/asynq_worker .` command copies the built binary from the builder stage into the final image.
- **Expose Port**: The `EXPOSE` directive specifies that the container should expose port 6379 (the default port for Redis, which is used by Asynq).
- **Run the Worker**: The `CMD` directive specifies the command to run the Asynq worker when the container starts.

Make sure to replace `./asynq_worker` with the correct path to your binary if it's different.
