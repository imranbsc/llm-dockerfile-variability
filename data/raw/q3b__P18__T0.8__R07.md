Certainly! Below is a Dockerfile for a background worker built in Go using the Asynq package. This Dockerfile sets up a Go environment, installs necessary dependencies, and defines how to run the worker.

```Dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.19-alpine

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install dependencies
RUN go get -u github.com/go-redis/redis/v8

# Build the Go application
RUN go build -o asynq_worker cmd/asynq_worker/main.go

# Expose the default port used by Asynq
EXPOSE 6379

# Define environment variables for Asynq
ENV ASYNQ_ADDR="redis://localhost:6379"
ENV ASYNQ_QUEUE_NAME="default"

# Run the application
CMD ["./asynq_worker"]
```

### Explanation:
- **Base Image**: The `golang:1.19-alpine` image is used as the base image, which is lightweight and optimized for Go applications.
- **Working Directory**: The `WORKDIR` directive sets the default directory for the container where the application will be built and run.
- **Copy Command**: The `COPY` command copies the contents of the current directory into the container at `/app`.
- **Go Dependencies**: The `go get` command installs the `github.com/go-redis/redis/v8` package, which is required for Asynq.
- **Build Command**: The `go build` command compiles the Go application into an executable named `asynq_worker`.
- **Expose Port**: The `EXPOSE` directive exposes port 6379, which is the default port used by Asynq for Redis.
- **Environment Variables**: The `ENV` directives set environment variables for the Asynq worker. `ASYNQ_ADDR` is the Redis connection string, and `ASYNQ_QUEUE_NAME` is the name of the queue to which the worker will listen.
- **Command to Run**: The `CMD` directive specifies the default command to run when the container starts, which is the compiled `asynq_worker` executable.

### Usage:
1. Save the Dockerfile in the root directory of your project.
2. Build the Docker image using the command: `docker build -t asynq_worker .`
3. Run the container using the command: `docker run -d --name asynq_worker asynq_worker`

This setup assumes that Redis is running locally on the host machine. You can adjust the Redis connection string in the `ENV` directive to connect to a remote Redis instance if needed.
