Certainly! Below is a simple Dockerfile for a background worker built in Go using Asynq. This Dockerfile assumes you have a Go application that uses Asynq for handling background tasks.

```Dockerfile
# Use an official Go image as the base image
FROM golang:1.17-alpine as build

# Set the working directory in the container
WORKDIR /app

# Copy the go.mod and go.sum files to the container
COPY go.mod go.sum .

# Install Go dependencies
RUN go mod download

# Copy the rest of your application code
COPY . .

# Build the Go application
RUN CGO_ENABLED=0 go build -o asynq-worker main.go

# Use an official Alpine image as the final image
FROM alpine:3.15

# Set the working directory in the container
WORKDIR /app

# Copy the built Go application from the build stage
COPY --from=build /app/asynq-worker .

# Expose the port that your application uses
EXPOSE 8080

# Run the application
CMD ["./asynq-worker"]
```

### Explanation:
1. **Base Image**: The Dockerfile starts with an official Go image (`golang:1.17-alpine`) as the base image. This is a lightweight Alpine Linux-based image with Go pre-installed.
2. **Working Directory**: The `WORKDIR` instruction sets the working directory in the container to `/app`.
3. **Copy Dependencies**: The `COPY go.mod go.sum .` command copies the `go.mod` and `go.sum` files to the container, which are used to manage dependencies.
4. **Install Dependencies**: The `RUN go mod download` command installs the Go dependencies specified in the `go.mod` file.
5. **Copy Application Code**: The `COPY . .` command copies all the files from the local directory to the container's `/app` directory.
6. **Build the Application**: The `RUN CGO_ENABLED=0 go build -o asynq-worker main.go` command builds the Go application, setting the CGO_ENABLED flag to 0 to disable cgo for better performance.
7. **Final Image**: The Dockerfile uses another Alpine image (`alpine:3.15`) as the final image.
8. **Working Directory**: The `WORKDIR` instruction again sets the working directory to `/app`.
9. **Copy Built Application**: The `COPY --from=build /app/asynq-worker .` command copies the built application from the build stage to the final image.
10. **Expose Port**: The `EXPOSE 8080` instruction exposes port 8080, which is the default port that your application uses.
11. **Run the Application**: The `CMD ["./asynq-worker"]` instruction specifies the command to run the application.

To build and run the Docker image, you can use the following commands:

```sh
# Build the Docker image
docker build -t asynq-worker .

# Run the Docker container
docker run -d --name asynq-worker asynq-worker
```

This will start a background worker container using the built image. Make sure to replace `main.go` with the actual name of your main Go file.
