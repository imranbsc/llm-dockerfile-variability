Certainly! Below is a Dockerfile for a background worker built in Go using Asynq. This Dockerfile assumes you have a Go application that uses Asynq for background task processing.

```Dockerfile
# Use an official Golang image as the base image
FROM golang:1.17-alpine as builder

# Set the working directory in the container
WORKDIR /go/src/app

# Copy the Go application source code into the container
COPY . .

# Install dependencies
RUN go get -u -v ./...

# Build the Go application
RUN CGO_ENABLED=0 go build -o asynq_worker

# Use an official Alpine image as the final image
FROM alpine:latest

# Set the working directory in the container
WORKDIR /app

# Copy the built Go application from the builder stage
COPY --from=builder /go/src/app/asynq_worker .

# Expose the port on which the application runs
EXPOSE 6379

# Run the application
CMD ["./asynq_worker"]
```

### Explanation:

1. **Base Image**: The `golang:1.17-alpine` image is used as the base for the build stage. Alpine is lightweight and is ideal for production environments.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory to `/go/src/app`, where the Go application source code will be copied.

3. **Copy Source Code**: The `COPY` instruction copies the entire project directory into the container.

4. **Install Dependencies**: The `go get -u -v ./...` command installs all dependencies listed in the `go.mod` file.

5. **Build the Application**: The `go build -o asynq_worker` command compiles the Go application into an executable named `asynq_worker`.

6. **Final Image**: The `alpine:latest` image is used as the base for the final image. This is a lightweight Alpine image that is suitable for running services.

7. **Working Directory in Final Image**: The `WORKDIR` instruction sets the working directory to `/app` in the final image.

8. **Copy Built Application**: The `COPY --from=builder /go/src/app/asynq_worker .` instruction copies the built `asynq_worker` executable from the build stage into the final image.

9. **Expose Port**: The `EXPOSE 6379` instruction tells Docker that the application listens on port 6379, which is the default port for Redis, which Asynq uses as the message broker.

10. **Run Command**: The `CMD ["./asynq_worker"]` instruction specifies the command to run the application when the container is started.
