```Dockerfile
# Use the official Go image as the base image
FROM golang:1.21 AS builder

# Set the working directory in the container
WORKDIR /go/src/app

# Copy the current directory contents into the container at /go/src/app
COPY . /go/src/app

# Build the Go application
RUN go build -o app ./cmd/app

# Use alpine as the final runtime image
FROM alpine:latest

# Copy the built application from the builder image to the final image
COPY --from=builder /go/src/app/app /app

# Set the entrypoint of the container
ENTRYPOINT ["/app"]
```

**Explanation**:
1. **Base Image**: The Dockerfile starts with the official Go 1.21 image as the base. This image includes the necessary tools and packages for building Go applications.
2. **Working Directory**: The `WORKDIR` instruction sets the directory where the container will start executing commands. Here, it's set to `/go/src/app`.
3. **Copy Code**: The `COPY` command copies the current directory into the container at the specified path. This includes all files and directories within the current directory.
4. **Build Application**: The `RUN` command executes the `go build` command to build the Go application. The `-o app` flag specifies the output name of the binary file as `app`.
5. **Final Runtime Image**: The `FROM alpine:latest` line specifies the final image, which is the smallest possible Alpine Linux image.
6. **Copy Built Application**: The `COPY --from=builder /go/src/app/app /app` command copies the binary from the builder image to the final image at the `/app` directory.
7. **Entrypoint**: The `ENTRYPOINT` instruction sets the default command to execute when the container starts, which is the binary file `/app`.

This Dockerfile is a simple example and can be expanded with additional configurations as needed, such as installing dependencies, configuring environment variables, or adding support for multi-stage builds.
