Certainly! Below is a Dockerfile for a command-line tool built in Go using the Cobra library. This Dockerfile assumes that you have a Go application that uses Cobra for command-line parsing and that you have a `go.mod` file.

```Dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.17-alpine as builder

# Set the working directory in the container
WORKDIR /go/src/app

# Copy the current directory contents into the container at /go/src/app
COPY . /go/src/app

# Install any needed packages specified in Gopkg.lock
RUN go mod tidy

# Build the Go application
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o /go/bin/app main.go

# Use an official Alpine image as a final runtime image
FROM alpine:latest

# Set the working directory in the container
WORKDIR /app

# Copy the pre-built binary from the builder stage
COPY --from=builder /go/bin/app /app/app

# Expose the port the application runs on
EXPOSE 8080

# Run the application
CMD ["./app"]
```

### Explanation:

1. **Base Image**: The `FROM golang:1.17-alpine` line uses the official Go image with Alpine Linux as the base image, which is lightweight and efficient for building Go applications.

2. **Working Directory**: `WORKDIR /go/src/app` sets the working directory in the container where your Go code will be compiled.

3. **Copy Code**: `COPY . /go/src/app` copies the current directory (containing your Go application) into the container at the specified working directory.

4. **Install Dependencies**: `RUN go mod tidy` ensures that all dependencies are installed according to the `go.mod` file.

5. **Build the Application**: `RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o /go/bin/app main.go` compiles the Go application into a binary named `app`. The `CGO_ENABLED=0` and `GOOS=linux GOARCH=amd64` flags ensure that the binary is built for Linux on an AMD64 architecture.

6. **Final Runtime Image**: `FROM alpine:latest` uses the Alpine Linux image as the final runtime image.

7. **Set Working Directory**: `WORKDIR /app` sets the working directory in the container for the runtime.

8. **Copy Binary**: `COPY --from=builder /go/bin/app /app/app` copies the pre-built binary from the builder stage into the final runtime image.

9. **Expose Port**: `EXPOSE 8080` makes the container listen on port 8080, which is where your application will run.

10. **Run the Application**: `CMD ["./app"]` specifies that the application should be run when the container starts.

You can build this Docker image using `docker build -t your-image-name .` and then run it with `docker run -p 8080:8080 your-image-name`.
