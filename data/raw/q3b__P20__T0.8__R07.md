Certainly! Below is a Dockerfile for a scheduled batch job built in Go using the `robfig/cron` library.

```Dockerfile
# Use a base image with a recent version of Go
FROM golang:1.17-alpine as builder

# Set the working directory in the container
WORKDIR /app

# Copy the Go source code into the container
COPY go.mod go.sum ./
RUN go mod download

# Copy the rest of the source code into the container
COPY . .

# Build the Go application
RUN CGO_ENABLED=0 go build -o app

# Use a minimal base image for running the application
FROM alpine:latest

# Set the working directory in the container
WORKDIR /app

# Copy the pre-built Go application from the builder stage
COPY --from=builder /app/app .

# Expose the port the application runs on
EXPOSE 8080

# Set the entry point for the application
CMD ["./app"]
```

### Explanation:
- **Base Image**: The Dockerfile starts with a recent version of the Go base image (`golang:1.17-alpine`).
- **Working Directory**: The `WORKDIR` is set to `/app` to organize files and commands.
- **Go Modules**: The `go.mod` and `go.sum` files are copied to ensure Go modules are downloaded.
- **Building the Application**: The application is built using `go build -o app`.
- **Minimal Runtime Image**: A minimal Alpine image is used for running the application.
- **Copying the Built Application**: The pre-built Go application from the builder stage is copied into the minimal image.
- **Port Exposure**: The application is exposed on port 8080.
- **Entry Point**: The entry point is set to run the application using `./app`.

### Running the Container:
To run the container, you can use the following command:

```sh
docker run -p 8080:8080 your-image-name
```

Replace `your-image-name` with the actual name of the Docker image you push to a registry or build locally.
