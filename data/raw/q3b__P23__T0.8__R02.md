Certainly! Below is a Dockerfile for a background worker built in PHP using Laravel queues. This example assumes you have a Laravel application set up and you want to run a worker that consumes jobs from a queue.

```Dockerfile
# Use an official PHP runtime as a parent image
FROM php:8.0-fpm

# Set the working directory in the container
WORKDIR /var/www/html

# Install dependencies
RUN apt-get update && \
    apt-get install -y libpq-dev && \
    docker-php-ext-install pdo_pgsql

# Copy the Composer file and install dependencies
COPY composer.lock composer.json ./
RUN composer install --no-dev --no-scripts

# Copy the rest of the application code
COPY . .

# Install node modules
RUN npm install

# Build the application for production
RUN npm run build

# Expose the default port for Laravel
EXPOSE 80

# Run the Laravel queue worker
CMD ["php", "artisan", "queue:work", "--daemon"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with an official PHP runtime image version 8.0-fpm, which is suitable for running a PHP application.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/var/www/html`, where the Laravel application will be placed.

3. **Dependencies**: The `apt-get` command installs `libpq-dev` for PostgreSQL support and `docker-php-ext-install pdo_pgsql` to enable the PDO PostgreSQL extension, which is necessary for connecting to a PostgreSQL database.

4. **Composer**: The `composer.lock` and `composer.json` files are copied to the container and used to install dependencies. The `--no-dev` and `--no-scripts` flags are used to skip development dependencies and scripts during installation.

5. **Application Code**: The rest of the application code is copied from the host to the container.

6. **Node Modules**: Node modules are installed using npm.

7. **Build**: The application is built for production using npm.

8. **Expose Port**: The container exposes port 80 to allow Laravel to serve the application.

9. **Command**: The `CMD` instruction specifies the command to run the Laravel queue worker in the background using `--daemon` to keep it running.

This Dockerfile should be placed in the root of your Laravel project and can be used to run a background worker for processing queue jobs.
