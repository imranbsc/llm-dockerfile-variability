Certainly! Below is a Dockerfile for a background worker built in PHP using Laravel queues. This Dockerfile assumes you have a Laravel project set up and you want to run a worker process that listens for queued jobs.

```dockerfile
# Use an official PHP runtime as a parent image
FROM php:8.1-fpm

# Install necessary dependencies
RUN apt-get update && apt-get install -y \
    libpq-dev \
    libzip-dev \
    && docker-php-ext-install pdo_mysql zip pdo_pgsql

# Copy the local code to the container at /var/www/html
COPY . /var/www/html

# Set the working directory in the container
WORKDIR /var/www/html

# Install Composer
RUN curl -sS https://getcomposer.org/installer | php -- --install-dir=/usr/local/bin --filename=composer

# Run Composer install
RUN composer install

# Install Laravel dependencies
RUN php artisan config:cache && php artisan route:cache && php artisan view:cache

# Expose the default Laravel port
EXPOSE 80

# Define environment variable for Laravel configuration
ENV APP_ENV=production

# Set the command to run the worker process
CMD ["php", "artisan", "queue:work"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with the official PHP 8.1-FPM image, which is a minimal PHP runtime with FPM support.

2. **Dependencies**: The image installs necessary packages such as `libpq-dev` for PostgreSQL, `libzip-dev` for handling ZIP archives, and PHP extensions like `pdo_mysql`, `zip`, and `pdo_pgsql` based on your database setup.

3. **Copy Project**: The local code is copied into the container at `/var/www/html`, which is the default web root directory for PHP-FPM.

4. **Composer Install**: Composer is installed and used to install project dependencies. Laravel configurations and routes are cached to improve performance.

5. **Environment Variable**: The `APP_ENV` environment variable is set to `production` to ensure Laravel is operating in a production environment.

6. **Worker Command**: The container runs the Laravel worker process using the command `php artisan queue:work`, which continuously listens for queued jobs and processes them.

### Usage:

To build and run the Docker container, follow these steps:

1. **Build the Docker Image**:
   ```sh
   docker build -t my-laravel-worker .
   ```

2. **Run the Docker Container**:
   ```sh
   docker run -d --name my-laravel-worker my-laravel-worker
   ```

3. **Configure Queue Workers**: You may need to configure the queue workers in your Laravel application to connect to your database and listen for jobs.

This Dockerfile provides a basic setup for a Laravel worker running in a container. You can further customize it based on your specific requirements, such as environment variables, volumes, or additional configurations.
