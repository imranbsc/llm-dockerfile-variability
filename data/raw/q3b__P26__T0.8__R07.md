Certainly! Below is a Dockerfile for a REST API built in C# using ASP.NET Core. This Dockerfile sets up a development environment for building and running a .NET Core application.

```Dockerfile
# Use the official Microsoft .NET Core runtime as a parent image
FROM mcr.microsoft.com/dotnet/aspnet:5.0 AS base

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . .

# Install any needed packages specified in requirements.txt
RUN dotnet restore

# Build the app
RUN dotnet build -c Release -o /app/out

# Copy the output of the build to the root directory
COPY --from=build /app/out .

# Expose the port the app runs on
EXPOSE 5000

# Run the app
ENTRYPOINT ["dotnet", "YourProjectName.dll"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with the official .NET Core runtime image (`mcr.microsoft.com/dotnet/aspnet:5.0`). This image is optimized for running a .NET Core application.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory within the container to `/app`. This is where the application code will be copied and executed.

3. **Copy Source Code**: The `COPY . .` command copies all the contents of the current directory (where the Dockerfile is located) into the `/app` directory inside the container.

4. **Restore Dependencies**: The `RUN dotnet restore` command installs all the dependencies specified in the `packages.config` file (or `project.json` for newer projects).

5. **Build the Application**: The `RUN dotnet build -c Release -o /app/out` command builds the application in release mode and outputs it to the `/app/out` directory.

6. **Copy Build Output**: The `COPY --from=build /app/out .` command copies the built output from the `build` stage into the `/app` directory.

7. **Expose Port**: The `EXPOSE 5000` instruction specifies that the application is listening on port 5000.

8. **Run the Application**: The `ENTRYPOINT ["dotnet", "YourProjectName.dll"]` command specifies the command to run when the container starts. Replace `YourProjectName.dll` with the actual name of your application's entry point.

### Note:
- Replace `YourProjectName.dll` with the actual name of your application's DLL file.
- Ensure that all necessary dependencies are listed in the `requirements.txt` file or `project.json` for the build to succeed.
