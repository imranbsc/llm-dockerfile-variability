Certainly! Below is a Dockerfile for a server-rendered web application built in C# using ASP.NET Core MVC. This Dockerfile assumes you have a .NET Core project set up and that you want to run the application in a container.

```Dockerfile
# Use an official .NET runtime as a parent image
FROM mcr.microsoft.com/dotnet/aspnet:5.0 AS base

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN dotnet restore

# Build the ASP.NET application for production
RUN dotnet publish -c Release -o out

# Copy the published application from the container to the output directory
WORKDIR /app/out

# Expose the port the application is running on
EXPOSE 80

# Run the application
CMD ["dotnet", "YourAppName.dll"]
```

### Explanation:
- **Base Image**: The `mcr.microsoft.com/dotnet/aspnet:5.0` image is used as the base image, which contains a runtime for ASP.NET Core applications.
- **Working Directory**: The `/app` directory is set as the working directory within the container.
- **Copy Project Files**: The `COPY . /app` command copies all files from the local directory to the container.
- **Restore Packages**: The `RUN dotnet restore` command installs the required NuGet packages specified in your project.
- **Publish Application**: The `RUN dotnet publish -c Release -o out` command builds the application in release mode and outputs it to the `out` directory.
- **Set Working Directory**: The `WORKDIR /app/out` command sets the working directory to the `out` directory where the published application is stored.
- **Expose Port**: The `EXPOSE 80` command specifies that the application listens on port 80.
- **Command to Run Application**: The `CMD ["dotnet", "YourAppName.dll"]` command specifies the command to run the application when the container starts.

Make sure to replace `YourAppName.dll` with the actual name of your application's DLL file. You can also customize the base image or add additional build steps as needed.
