Certainly! Below is a Dockerfile for a background worker built in C# using the .NET Worker Service template. This Dockerfile uses the official Microsoft .NET image and sets up the environment for running a .NET Worker Service application.

```Dockerfile
# Use the official .NET SDK image
FROM mcr.microsoft.com/dotnet/sdk:5.0 AS build

# Set the working directory
WORKDIR /app

# Copy the project file and restore packages
COPY *.csproj ./
RUN dotnet restore

# Copy the rest of the application source code
COPY . ./

# Build the application
RUN dotnet publish -c Release -o out

# Use the official .NET runtime image
FROM mcr.microsoft.com/dotnet/aspnet:5.0 AS runtime

# Set the working directory
WORKDIR /app

# Copy the published application from the build stage
COPY --from=build /app/out .

# Expose the port your application runs on
EXPOSE 80

# Run the application
ENTRYPOINT ["dotnet", "WorkerServiceApplication.dll"]
```

### Explanation:

1. **Base Image**: 
   - The Dockerfile starts with the official .NET SDK image (`mcr.microsoft.com/dotnet/sdk:5.0`) for building the application.
   - The `runtime` image (`mcr.microsoft.com/dotnet/aspnet:5.0`) is used to run the application once it's built.

2. **Working Directory**:
   - The `WORKDIR` instruction sets the working directory inside the container where the application files will be copied and the build process will run.

3. **Copying Project Files**:
   - The `COPY *.csproj ./` command copies the `*.csproj` file into the container.
   - The `RUN dotnet restore` command restores the dependencies specified in the `*.csproj` file.

4. **Copying Application Source**:
   - The `COPY . ./` command copies the rest of the application source code into the container.

5. **Building the Application**:
   - The `RUN dotnet publish -c Release -o out` command publishes the application into the `out` directory with the release configuration.

6. **Final Runtime Image**:
   - The `FROM` instruction specifies the final runtime image (`mcr.microsoft.com/dotnet/aspnet:5.0`).
   - The `WORKDIR` instruction sets the working directory inside the runtime image.

7. **Copying Published Application**:
   - The `COPY --from=build /app/out .` command copies the published application files from the build stage into the runtime image.

8. **Exposing Port**:
   - The `EXPOSE 80` instruction tells the container that the application will run on port 80.

9. **Running the Application**:
   - The `ENTRYPOINT ["dotnet", "WorkerServiceApplication.dll"]` instruction specifies the entry point for the container, which is the `WorkerServiceApplication.dll` file.

This Dockerfile assumes that your application is a .NET Worker Service project and that the application's entry point is specified in the `Program.cs` file. Adjust the paths and file names as necessary for your specific project structure.
