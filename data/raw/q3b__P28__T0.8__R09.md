Certainly! Below is a simple Dockerfile for a background worker built in C# using the .NET Worker Service template. This Dockerfile assumes you have a `.csproj` file in your project directory.

```Dockerfile
# Use the latest .NET SDK as the base image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the csproj file and restore dependencies
COPY *.csproj .
RUN dotnet restore

# Copy the rest of the application source code
COPY . .

# Build the application
RUN dotnet build -c Release -o out

# Use a separate runtime image for the final application
FROM mcr.microsoft.com/dotnet/aspnet:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build environment
COPY --from=build-env /app/out .

# Expose the port your application listens on
EXPOSE 80

# Run the application
ENTRYPOINT ["dotnet", "YourWorkerProject.dll"]
```

### Explanation:

1. **Base Image**: The `mcr.microsoft.com/dotnet/sdk:6.0` image is used as the base for building the application. This includes the .NET SDK.

2. **Working Directory**: The `WORKDIR` instruction sets the directory where the build and run commands will execute.

3. **Restore Dependencies**: The `dotnet restore` command is used to restore the project dependencies.

4. **Copy Source Code**: The `COPY` command copies all files from the current directory into the container.

5. **Build the Application**: The `dotnet build` command is used to build the application in the release configuration.

6. **Runtime Image**: A separate `mcr.microsoft.com/dotnet/aspnet:6.0` image is used for the final application. This includes the .NET runtime.

7. **Working Directory**: The `WORKDIR` instruction sets the working directory for the application.

8. **Copy Published Application**: The `COPY --from=build-env` command copies the published application from the build environment.

9. **Expose Port**: The `EXPOSE` instruction specifies the port the application listens on.

10. **Run the Application**: The `ENTRYPOINT` instruction specifies the command to run when the container starts.

Make sure to replace `YourWorkerProject.dll` with the actual name of your worker project's DLL file.
