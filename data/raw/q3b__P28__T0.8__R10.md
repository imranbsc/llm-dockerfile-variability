Certainly! Below is a Dockerfile for a background worker built in C# using the .NET Worker Service template. This Dockerfile assumes you have a .NET Worker Service project set up in your solution.

```dockerfile
# Use a base image with .NET SDK
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the project file and restore the necessary dependencies
COPY . .

# Build the project
RUN dotnet build --configuration Release

# Use a base image with .NET runtime
FROM mcr.microsoft.com/dotnet/aspnet:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the output from the build environment
COPY --from=build-env /app/bin/Release/net6.0/publish .

# Run the application
ENTRYPOINT ["dotnet", "MyWorkerService.dll"]
```

### Explanation:
- **Base Images**: 
  - `mcr.microsoft.com/dotnet/sdk:6.0`: This image contains the .NET SDK, which is necessary for building the application.
  - `mcr.microsoft.com/dotnet/aspnet:6.0`: This image contains the .NET runtime, which is used to run the application.

- **Working Directory**: The `WORKDIR` instruction sets the working directory in the container to `/app`, which is where the project files and dependencies will be copied.

- **Copying Project Files**: The `COPY . .` command copies all files from the host to the container, including the project file and its dependencies.

- **Building the Project**: The `RUN dotnet build --configuration Release` command builds the project in Release configuration.

- **Copying Output**: The `COPY --from=build-env /app/bin/Release/net6.0/publish .` command copies the output of the build (the compiled application) from the build environment to the container.

- **Running the Application**: The `ENTRYPOINT ["dotnet", "MyWorkerService.dll"]` command specifies the command to run when the container starts, which in this case is to execute the `MyWorkerService.dll` application.

Make sure to replace `MyWorkerService` with the actual name of your worker service project. Also, ensure that your project is correctly set up with a `.csproj` file in the `src` directory if it is part of a larger solution.
