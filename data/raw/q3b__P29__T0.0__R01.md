Certainly! Below is a Dockerfile for a command-line tool built in C# using the `System.CommandLine` library. This Dockerfile assumes you have a C# project that uses `System.CommandLine` and that you want to build and run it in a Docker container.

```Dockerfile
# Use a base image with .NET SDK
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the project file and restore dependencies
COPY *.csproj ./
RUN dotnet restore

# Copy the rest of the project files and build
COPY . ./
RUN dotnet publish -c Release -o out

# Use a minimal base image for the runtime
FROM mcr.microsoft.com/dotnet/runtime:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build environment
COPY --from=build-env /app/out .

# Expose the port the application runs on
EXPOSE 5000

# Run the application
ENTRYPOINT ["dotnet", "YourAppName.dll"]
```

### Explanation:

1. **Base Image**: The `mcr.microsoft.com/dotnet/sdk:6.0` image is used as the base image for building the application. This image includes the .NET SDK, which is necessary to compile the C# application.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory in the container to `/app`, which is where the project files will be copied and built.

3. **Restore Dependencies**: The `dotnet restore` command is used to restore the project dependencies from the `*.csproj` file.

4. **Copy and Build**: The `COPY` command copies the project files and the `dotnet publish` command builds the application in release mode and outputs it to the `out` directory.

5. **Runtime Image**: The `mcr.microsoft.com/dotnet/runtime:6.0` image is used as the base image for running the application. This image includes the .NET runtime, which is necessary to execute the compiled application.

6. **Working Directory**: The `WORKDIR` instruction sets the working directory in the container to `/app`, which is where the published application will be copied.

7. **Copy Published Application**: The `COPY --from=build-env /app/out .` command copies the published application from the build environment to the runtime environment.

8. **Expose Port**: The `EXPOSE` instruction specifies that the application listens on port 5000.

9. **Run Application**: The `ENTRYPOINT` instruction specifies the command to run the application, which is `dotnet YourAppName.dll`. Replace `YourAppName.dll` with the actual name of your application's DLL file.

### Building and Running the Docker Image:

To build the Docker image, navigate to the directory containing the Dockerfile and run the following command:

```sh
docker build -t your-app-name .
```

To run the Docker container, use the following command:

```sh
docker run -p 5000:5000 your-app-name
```

This will start the application and make it accessible on `http://localhost:5000`.
