Certainly! Below is a Dockerfile for a C# command-line tool built using System.CommandLine. This Dockerfile assumes you have a C# project set up with System.CommandLine as a dependency.

```Dockerfile
# Use the official .NET runtime as a parent image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . .

# Restore the NuGet packages
RUN dotnet restore

# Build the application
RUN dotnet publish -c Release -o out

# Use a multi-stage build to create a smaller final image
FROM mcr.microsoft.com/dotnet/runtime:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build-env container
COPY --from=build-env /app/out .

# Make port 80 available to the world outside this container
EXPOSE 80

# Run the application
ENTRYPOINT ["dotnet", "YourAppName.dll"]
```

### Explanation:

1. **Base Image**: The `mcr.microsoft.com/dotnet/sdk:6.0` image is used as the base image for building the application. This image includes the .NET SDK, which is necessary to build the application.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory in the container to `/app`, which is where the application will be built and run.

3. **Copy Files**: The `COPY` instruction copies the contents of the current directory into the container at `/app`.

4. **Restore NuGet Packages**: The `dotnet restore` command restores the NuGet packages specified in the `packages.config` or `project.json` file.

5. **Build the Application**: The `dotnet publish` command builds the application in release mode and outputs the result to the `out` directory.

6. **Multi-Stage Build**: The `mcr.microsoft.com/dotnet/runtime:6.0` image is used as the final image for running the application. This image includes the .NET runtime, which is smaller than the SDK image.

7. **Copy Published Application**: The `COPY --from=build-env /app/out .` instruction copies the published application from the build-env container to the final image.

8. **Expose Port**: The `EXPOSE` instruction makes port 80 available to the world outside this container.

9. **Run the Application**: The `ENTRYPOINT` instruction specifies the command to run the application, which is `dotnet YourAppName.dll`.

### Notes:
- Replace `YourAppName.dll` with the actual name of your application's DLL file.
- Ensure that your C# project is set up to use System.CommandLine as a dependency.
- You may need to adjust the .NET SDK version in the base image if you are using a different version of .NET.
