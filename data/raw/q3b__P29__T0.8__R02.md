Certainly! Below is a Dockerfile for a command-line tool built in C# using the `System.CommandLine` library. This Dockerfile assumes you have a basic C# project setup with a `.csproj` file.

```Dockerfile
# Use the official .NET runtime as the base image
FROM mcr.microsoft.com/dotnet/runtime:5.0 AS base

# Set the working directory in the container
WORKDIR /app

# Copy the csproj and restore the dependencies
COPY *.csproj ./
RUN dotnet restore

# Copy the rest of the project files and build
COPY . ./
RUN dotnet publish -c Release -o /app/publish

# Expose the port your application runs on
EXPOSE 5000

# Run the application
ENTRYPOINT ["dotnet", "publish/YourAppName.dll"]
```

### Explanation:
- **Base Image**: The Dockerfile starts with the official .NET runtime image (`mcr.microsoft.com/dotnet/runtime:5.0`). This image provides a minimal runtime environment for .NET applications.
- **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/app`, which is where your project files will be copied and built.
- **Restore Dependencies**: The `RUN dotnet restore` command restores all the dependencies specified in your `*.csproj` file.
- **Copy Project Files**: The `COPY . .` command copies all files from the host machine to the container's working directory.
- **Build Project**: The `RUN dotnet publish -c Release -o /app/publish` command builds the project in release mode and outputs the result to `/app/publish`.
- **Expose Port**: The `EXPOSE 5000` command informs the container that the application listens on port 5000.
- **Run Application**: The `ENTRYPOINT` command specifies the command to run when the container starts, which in this case is to execute the built application.

### Notes:
- Replace `YourAppName.dll` with the actual name of your application's main executable.
- Make sure your C# project is set to publish to the `publish` directory.
- You may need to adjust the .NET version and working directory based on your specific project requirements.
