Certainly! Below is a Dockerfile for a command-line tool built in C# using `System.CommandLine`. This Dockerfile assumes you have a C# project using `System.CommandLine` and that you want to package it into a Docker image.

```Dockerfile
# Use a .NET SDK as the base image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the project file and dependencies
COPY *.csproj ./
RUN dotnet restore

# Copy the source code
COPY . .

# Build the application
RUN dotnet publish -c Release -o out

# Use a minimal .NET runtime image for the final container
FROM mcr.microsoft.com/dotnet/runtime:6.0 AS final

# Set the working directory in the container
WORKDIR /app

# Copy the output from the build-env image
COPY --from=build-env /app/out .

# Expose the port the application runs on
EXPOSE 5000

# Run the application
ENTRYPOINT ["dotnet", "YourAppName.dll"]
```

### Explanation:

1. **Base Image**: The `mcr.microsoft.com/dotnet/sdk:6.0` image is used as the base for building the application. This image includes the .NET SDK, which is necessary to build the application.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory within the container to `/app`, where the project files and dependencies will be copied.

3. **Restore Dependencies**: The `COPY *.csproj . /` command copies the `csproj` file and other necessary files to the container. The `RUN dotnet restore` command restores the project's dependencies from the NuGet package manager.

4. **Copy Source Code**: The `COPY . .` command copies the entire source code of the project into the container.

5. **Build the Application**: The `RUN dotnet publish -c Release -o out` command compiles the application into a publish directory named `out`.

6. **Final Image**: The `mcr.microsoft.com/dotnet/runtime:6.0` image is used as the base for the final container. This image includes the .NET runtime, which is sufficient to run the application.

7. **Working Directory in Final Image**: The `WORKDIR /app` instruction sets the working directory in the final container to `/app`.

8. **Copy Output**: The `COPY --from=build-env /app/out .` command copies the output of the build process from the `build-env` image to the final image.

9. **Expose Port**: The `EXPOSE 5000` instruction indicates that the application listens on port 5000.

10. **Entrypoint**: The `ENTRYPOINT ["dotnet", "YourAppName.dll"]` command specifies the command to run the application when the container starts.

Replace `YourAppName.dll` with the actual name of your application's main executable.
