Certainly! Below is a Dockerfile for building a command-line tool in C# using `System.CommandLine`. This Dockerfile assumes that you have a C# project that uses `System.CommandLine` and that the project is set up to build a console application.

```dockerfile
# Use a base image for .NET Core
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /src

# Copy the project files into the container
COPY . .

# Build the project
RUN dotnet build --configuration Release

# Create a runtime image
FROM mcr.microsoft.com/dotnet/aspnet:6.0

# Set the working directory in the runtime image
WORKDIR /app

# Copy the built application from the build-env to the runtime image
COPY --from=build-env /src/bin/Release/net6.0/publish .

# Expose the default port for the command-line tool
EXPOSE 5000

# Define the entry point for the container
ENTRYPOINT ["./your-tool.exe"]
```

### Explanation:

1. **Base Image**: The `build-env` stage uses the `.NET Core SDK` image. This stage is used to compile the C# project.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory inside the container to `/src`, where the project files will be copied.

3. **Copy Project Files**: The `COPY . .` command copies all files and directories from the local machine to the container.

4. **Build the Project**: The `dotnet build --configuration Release` command compiles the project in release configuration.

5. **Runtime Image**: The `runtime-env` stage uses the `.NET Core ASP.NET` image. This stage is used to run the compiled application.

6. **Working Directory**: The `WORKDIR` instruction sets the working directory in the runtime image to `/app`.

7. **Copy Built Application**: The `COPY --from=build-env /src/bin/Release/net6.0/publish .` command copies the compiled application from the build environment to the runtime environment.

8. **Expose Port**: The `EXPOSE 5000` command tells Docker that the application listens on port 5000.

9. **Define Entry Point**: The `ENTRYPOINT ["./your-tool.exe"]` command specifies the entry point for the container, which is the entry point of the executable built by the C# project.

Make sure to replace `./your-tool.exe` with the actual name of your executable in the application. Also, adjust the .NET SDK and runtime versions as needed for your project.
