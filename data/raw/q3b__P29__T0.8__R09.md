Certainly! Below is a simple Dockerfile for a C# command-line tool built using `System.CommandLine`. This example assumes you have a basic understanding of C# and `System.CommandLine`.

```Dockerfile
# Use the official .NET SDK image as the base image
FROM mcr.microsoft.com/dotnet/sdk:5.0 AS build-env

# Set the working directory in the container
WORKDIR /src

# Copy the project file and dependencies
COPY *.csproj .
COPY ./tools/*.csproj ./tools/
COPY ./properties/*.csproj ./properties/

# Restore all dependencies
RUN dotnet restore

# Build the application
RUN dotnet publish -c Release -o out

# Use a multi-stage build to create a smaller final image
FROM mcr.microsoft.com/dotnet/runtime:5.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build-env container
COPY --from=build-env /src/out .

# Expose the port that your application listens on
EXPOSE 5000

# Run the application
ENTRYPOINT ["dotnet", "YourToolName.dll"]
```

### Explanation:
- **Base Image**: The `mcr.microsoft.com/dotnet/sdk:5.0` image is used for building the application. You can change the version as needed.
- **Working Directory**: The working directory is set to `/src` where your project files are located.
- **Dependencies**: The `COPY` commands copy the project files and their dependencies into the container.
- **Restore**: The `dotnet restore` command restores all dependencies specified in the project files.
- **Build**: The `dotnet publish` command builds the application in release mode and outputs it to the `out` directory.
- **Final Image**: The `mcr.microsoft.com/dotnet/runtime:5.0` image is used to create a smaller final image that runs the application.
- **Working Directory in Final Image**: The working directory in the final image is set to `/app`, where the published application is copied.
- **Expose**: The `EXPOSE` command exposes port `5000`, which is the default port for .NET applications.
- **Entry Point**: The `ENTRYPOINT` command specifies the entry point for the container, which is the executable file `YourToolName.dll`.

Make sure to replace `YourToolName.dll` with the actual name of your executable file.
