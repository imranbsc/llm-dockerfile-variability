```Dockerfile
# Use an official .NET runtime as a parent image
FROM mcr.microsoft.com/dotnet/sdk:5.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . .

# Install any needed packages specified in requirements.txt
RUN dotnet restore

# Build the application
RUN dotnet publish -c Release -o out

# Use a multi-stage build to create a smaller final image
FROM mcr.microsoft.com/dotnet/aspnet:5.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build-env container
COPY --from=build-env /app/out .

# Expose the port the application runs on
EXPOSE 80

# Run the application
ENTRYPOINT ["dotnet", "YourApp.dll"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with the official .NET SDK image. This image contains the necessary tools and libraries to build and run .NET applications.

2. **Working Directory**: The `WORKDIR` instruction sets the working directory in the container to `/app`, which is where the application files will be copied and built.

3. **Copy Files**: The `COPY` instruction copies the current directory contents into the container at `/app`. This includes the `Dockerfile` and any other necessary files.

4. **Restore Packages**: The `RUN` instruction uses `dotnet restore` to restore the project dependencies specified in `requirements.txt`.

5. **Build the Application**: The `RUN` instruction uses `dotnet publish` to build the application in release mode and output it to the `out` directory.

6. **Multi-Stage Build**: The Dockerfile uses a multi-stage build to create a smaller final image. The `FROM` instruction specifies the base image for the final image, which is the official .NET runtime image.

7. **Copy Published Application**: The `COPY --from=build-env /app/out .` instruction copies the published application from the build-env container to the final image.

8. **Expose Port**: The `EXPOSE` instruction specifies the port the application runs on, which is `80` in this case.

9. **Run the Application**: The `ENTRYPOINT` instruction specifies the command to run the application when the container starts.
