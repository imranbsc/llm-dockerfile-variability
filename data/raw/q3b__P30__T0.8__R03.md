Certainly! Below is a Dockerfile that builds a C# application using Quartz.NET for a scheduled batch job. This Dockerfile assumes you have a basic understanding of Docker and C#.

```Dockerfile
# Use the official .NET runtime as a parent image
FROM mcr.microsoft.com/dotnet/sdk:5.0 AS build-env

# Set the working directory in the container
WORKDIR /src

# Copy the current directory contents into the container at /src
COPY . .

# Build the application
RUN dotnet restore
RUN dotnet publish -c Release -o out

# Create a non-root user
RUN useradd -r --no-create-home appuser
USER appuser

# Use the official .NET runtime as a final runtime image
FROM mcr.microsoft.com/dotnet/aspnet:5.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build environment
COPY --from=build-env /src/out ./

# Expose the port the application runs on
EXPOSE 80

# Run the application
CMD ["dotnet", "YourApp.dll"]
```

### Explanation:

1. **Base Image**: The `mcr.microsoft.com/dotnet/sdk:5.0` image is used for building the application. It includes the .NET SDK, which is required to compile and package the application.

2. **Working Directory**: The `WORKDIR /src` sets the working directory to `/src` in the container.

3. **Copy Files**: The `COPY . .` command copies all files from the local directory to the container's `/src` directory.

4. **Build Application**: The `RUN dotnet restore` command restores the project dependencies. The `RUN dotnet publish -c Release -o out` command publishes the application in release mode to the `out` directory.

5. **Create Non-root User**: The `useradd -r --no-create-home appuser` command creates a non-root user named `appuser` who will run the application. This is a good security practice to avoid running applications as the root user.

6. **Final Runtime Image**: The `mcr.microsoft.com/dotnet/aspnet:5.0` image is used for running the application. This image includes the .NET runtime, which is necessary to execute the compiled application.

7. **Working Directory in Runtime Image**: The `WORKDIR /app` sets the working directory to `/app` in the container.

8. **Copy Published Application**: The `COPY --from=build-env /src/out .` command copies the published application from the build environment to the runtime container.

9. **Expose Port**: The `EXPOSE 80` command makes port 80 available to the container, which is the default port for web applications.

10. **Run Application**: The `CMD ["dotnet", "YourApp.dll"]` command specifies the entry point for the container, which runs the application using the `dotnet` command.

Replace `YourApp.dll` with the actual name of your application's DLL file. This Dockerfile assumes your application is a console application or a Windows Forms application, as it uses the `.NET SDK`. If your application is a web application, you might need to adjust the `CMD` line to run the application using the `dotnet` web server.
