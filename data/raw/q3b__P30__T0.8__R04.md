```Dockerfile
# Use an official .NET runtime as a parent image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . .

# Restore the NuGet packages
RUN dotnet restore

# Build the application
RUN dotnet publish -c Release -o out

# Create a runtime container
FROM mcr.microsoft.com/dotnet/runtime:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build-env container
COPY --from=build-env /app/out .

# Run the application
ENTRYPOINT ["dotnet", "CSharpScheduledJob.dll"]
```

**Explanation**:
- **Step 1:** We start with an official .NET SDK image for building our application.
- **Step 2:** We set our working directory to `/app`.
- **Step 3:** We copy the current directory contents into the container at `/app`.
- **Step 4:** We restore the NuGet packages using `dotnet restore`.
- **Step 5:** We build the application using `dotnet publish` and output the files to `/app/out`.
- **Step 6:** We create a runtime image from the .NET runtime image.
- **Step 7:** We set the working directory to `/app`.
- **Step 8:** We copy the published application from the build environment container to the runtime container.
- **Step 9:** We set the entry point to run the application using `dotnet CSharpScheduledJob.dll`. Make sure `CSharpScheduledJob.dll` is the name of your executable.
