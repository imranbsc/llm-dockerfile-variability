Certainly! Below is a simple Dockerfile for a scheduled batch job built in C# using Quartz.NET. This Dockerfile assumes you have a basic understanding of C#, Quartz.NET, and Docker.

```Dockerfile
# Use an official .NET runtime as a parent image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /src

# Copy the current directory contents into the container at /src
COPY . .

# Build the C# application
RUN dotnet restore
RUN dotnet publish -c Release -o /app

# Use a lightweight runtime as a final image
FROM mcr.microsoft.com/dotnet/aspnet:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the output of the build into the final image
COPY --from=build-env /app .

# Expose the default port for Quartz.NET's scheduler
EXPOSE 5000

# Run the Quartz.NET scheduler
CMD ["dotnet", "YourApp.dll"]
```

### Explanation:
- **Base Image**: The Dockerfile starts with the official .NET SDK image. You can use a different version of the SDK if needed.
- **Working Directory**: The working directory is set to `/src` where your C# code is located.
- **Copy Sources**: The `COPY . .` command copies the current directory contents into the container.
- **Build**: The `dotnet restore` and `dotnet publish` commands build the C# application.
- **Final Image**: The final image is built using the official .NET runtime image.
- **Working Directory**: The working directory is set to `/app` in the final image.
- **Copy Outputs**: The output of the build is copied from the build environment to the final image.
- **Expose Port**: Quartz.NET runs on port 5000, so this port is exposed.
- **Run Command**: The `CMD` command specifies the command to run the application when the container starts.

### Notes:
- Replace `YourApp.dll` with the actual name of your C# application.
- This Dockerfile assumes you have a `Program.cs` or `App.cs` file in your project with a `Main` method that sets up and starts the Quartz.NET scheduler.
- You may need to adjust the `WORKDIR` and `COPY` commands if your project structure is different.
