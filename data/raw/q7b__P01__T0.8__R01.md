Certainly! Below is a Dockerfile for a REST API built in Node.js using Express:

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14

# Set the working directory in the container
WORKDIR /usr/src/app

# Copy package.json and package-lock.json
COPY package*.json ./

# Install any needed packages specified in package.json
RUN npm install

# Bundle app source inside Docker image
COPY . .

# Make port 3000 available to the world outside this container
EXPOSE 3000

# Define environment variable
ENV NAME World

# Run app when the container launches
CMD ["node", "index.js"]
```

### Explanation:
1. **FROM node:14**: This line sets up a Docker image using Node.js version 14.
2. **WORKDIR /usr/src/app**: This sets the working directory inside the container.
3. **COPY package*.json ./**: This copies the `package.json` and `package-lock.json` (if present) into the working directory.
4. **RUN npm install**: This runs `npm install` to install all the dependencies.
5. **COPY . .**: This copies the rest of the application code into the container.
6. **EXPOSE 3000**: This exposes port 3000, which is where your Express server is likely to be running.
7. **ENV NAME World**: This sets an environment variable that can be used in your application.
8. **CMD ["node", "index.js"]**: This specifies the command to run your application when the container starts.

Make sure your `index.js` file is your entry point for the Node.js application, and it sets up your Express server accordingly.
