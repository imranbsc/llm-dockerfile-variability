Certainly! Below is a Dockerfile for a command-line tool built in Node.js using Commander.js. This Dockerfile assumes you have a `package.json` file in your project root, which includes Commander.js as a dependency.

```Dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14 as builder

# Set the working directory in the container
WORKDIR /app

# Copy the package.json and package-lock.json to the working directory
COPY package*.json ./

# Install any needed packages specified in package.json
RUN npm install

# Bundle app source inside Docker image
COPY . .

# Build the application (if needed)
# RUN npm run build

# Switch to a non-root user
USER node

# Define environment variable
ENV NODE_ENV=production

# Expose the port the app runs on
EXPOSE 3000

# Command to run the app
CMD ["node", "index.js"]
```

### Explanation:
1. **FROM node:14 as builder**: Uses the official Node.js 14 image as the base image.
2. **WORKDIR /app**: Sets the working directory inside the container to `/app`.
3. **COPY package*.json ./**: Copies the `package.json` and `package-lock.json` files to the working directory.
4. **RUN npm install**: Installs the dependencies specified in `package.json`.
5. **COPY . .**: Copies the rest of the application code into the container.
6. **USER node**: Switches to a non-root user named `node`.
7. **ENV NODE_ENV=production**: Sets the environment variable `NODE_ENV` to `production`.
8. **EXPOSE 3000**: Exposes port 3000.
9. **CMD ["node", "index.js"]**: Specifies the command to run the application when the container starts.

### Notes:
- Ensure your `index.js` file is the entry point of your application.
- If your application has any build steps (e.g., compiling TypeScript), you would include those steps after the `npm install` line.
- Adjust the `EXPOSE` line if your application runs on a different port.

This Dockerfile should work for a typical Node.js application built with Commander.js.
