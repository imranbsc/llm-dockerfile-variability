```dockerfile
# Use an official Node.js runtime as a parent image
FROM node:14-alpine as builder

# Set the working directory in the container
WORKDIR /app

# Copy package.json and package-lock.json (if any) to the working directory
COPY package*.json ./

# Install production dependencies
RUN npm install --only=production

# Bundle app source code
COPY . .

# Use a smaller image for the production environment
FROM node:14-alpine

# Set the working directory in the container
WORKDIR /app

# Copy the dependencies from the builder stage
COPY --from=builder /app/node_modules ./node_modules

# Copy the rest of the application code
COPY --from=builder /app ./

# Expose the port that your application runs on
EXPOSE 8080

# Command to run your application
CMD ["node", "your-entry-script.js"]
```

### Explanation:

1. **Builder Stage**:
   - `FROM node:14-alpine`: Start with an official Node.js 14 image based on Alpine Linux.
   - `WORKDIR /app`: Set the working directory inside the container.
   - `COPY package*.json ./`: Copy the `package.json` and `package-lock.json` (if any) to the working directory.
   - `RUN npm install --only=production`: Install only the production dependencies.
   - `COPY . .`: Copy the rest of the application code to the working directory.

2. **Production Stage**:
   - `FROM node:14-alpine`: Start with an official Node.js 14 image based on Alpine Linux.
   - `WORKDIR /app`: Set the working directory inside the container.
   - `COPY --from=builder /app/node_modules ./node_modules`: Copy the dependencies from the builder stage.
   - `COPY --from=builder /app ./:` Copy the rest of the application code from the builder stage.
   - `EXPOSE 8080`: Expose the port that your application runs on.
   - `CMD ["node", "your-entry-script.js"]`: Command to run your application.

### Notes:
- Replace `your-entry-script.js` with the actual entry point of your Node.js application.
- Ensure that your `package.json` has the correct `start` script if you are not explicitly running a script.
- If your batch job runs at a specific time, you can add a cron job within your script or use a separate container to schedule the job.
