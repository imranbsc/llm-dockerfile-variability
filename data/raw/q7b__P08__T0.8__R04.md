Certainly! Below is a Dockerfile for a background worker built in Python using Celery:

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --trusted-host pypi.python.org -r requirements.txt

# Make port 8080 available to the world outside this container
EXPOSE 8080

# Define environment variable
ENV NAME World

# Run app.py when the container launches
CMD ["celery", "-A", "your_project_name.celery", "worker", "--loglevel=info"]
```

Make sure to replace `your_project_name.celery` with the actual import path to your Celery application.

### Explanation:
1. **FROM python:3.9-slim**: Use an official Python 3.9 image as the base image.
2. **WORKDIR /app**: Set the working directory inside the container.
3. **COPY . /app**: Copy the current directory contents into the container at `/app`.
4. **RUN pip install --trusted-host pypi.python.org -r requirements.txt**: Install the dependencies listed in `requirements.txt`.
5. **EXPOSE 8080**: Make port 8080 available to the world outside this container.
6. **ENV NAME World**: Set an environment variable `NAME` with a default value of `World`.
7. **CMD ["celery", "-A", "your_project_name.celery", "worker", "--loglevel=info"]**: Command to run the Celery worker when the container starts.

### Build and Run:
To build and run the Docker container:

1. Build the Docker image:
   ```sh
   docker build -t your_image_name .
   ```

2. Run the Docker container:
   ```sh
   docker run -d --name your_container_name -p 8080:8080 your_image_name
   ```

This will create and run a Docker container with your Celery background worker.
