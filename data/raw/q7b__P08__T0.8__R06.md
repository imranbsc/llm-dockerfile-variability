Here is a basic example of a Dockerfile for a background worker built in Python using Celery:

```Dockerfile
# Use an official Python runtime as a parent image
FROM python:3.8-slim

# Set the working directory in the container
WORKDIR /app

# Copy the current directory contents into the container at /app
COPY . /app

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Make port 80 available to the world outside this container
EXPOSE 80

# Define environment variable
ENV NAME World

# Run app.py when the container launches
CMD ["celery", "-A", "tasks", "worker", "--loglevel=info"]
```
This Dockerfile assumes that your Python application's Celery tasks are defined in a file called `tasks.py` in the same directory as the Dockerfile. You would need to replace `tasks.py` with the actual name of your Celery app if it's different.

Also, make sure your `requirements.txt` file includes all of the packages needed for your application. This Dockerfile uses `pip` to install the packages, but you could use `conda` if you are using Anaconda.

This Dockerfile does not handle the broker and result backend for Celery. You would need to define these in your Celery configuration or pass them as environment variables when running the container.
