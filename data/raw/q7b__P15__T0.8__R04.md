Certainly! Below is a Dockerfile for a scheduled batch job built in Java using Spring Batch. This Dockerfile assumes you have a Maven project and that you are using a multi-stage build to keep the image size small.

```Dockerfile
# Use an official OpenJDK image as the base image
FROM openjdk:17-jdk-slim AS build

# Set the working directory in the container
WORKDIR /app

# Copy the local Maven repository to the container to avoid downloading dependencies every time
COPY settings.xml /usr/share/maven/ref/settings.xml

# Copy the project's pom.xml and all src files into the container
COPY pom.xml .
COPY src src

# Build the project
RUN mvn clean package -DskipTests

# Use a smaller image for the final image
FROM openjdk:17-jre-slim

# Copy the built JAR file from the build stage
COPY --from=build /app/target/your-application.jar /app/your-application.jar

# Set the working directory in the container
WORKDIR /app

# Define the environment variables
ENV JAVA_OPTS="-Djava.security.egd=file:/dev/./urandom"

# Expose the application port
EXPOSE 8080

# Schedule the batch job using cron
RUN echo "0 * * * * java $JAVA_OPTS -jar your-application.jar --spring.profiles.active=prod" > /etc/cron.d/spring-batch-job

# Make the cron file executable
RUN chmod 0644 /etc/cron.d/spring-batch-job

# Install cron
RUN apt-get update && apt-get install -y cron && rm -rf /var/lib/apt/lists/*

# Start cron and the application
CMD ["sh", "-c", "cron && java $JAVA_OPTS -jar your-application.jar --spring.profiles.active=prod"]
```

### Explanation:
1. **Base Image**: The `openjdk:17-jdk-slim` image is used for building the project. This image is selected because it includes Maven and the JDK.
2. **Working Directory**: `/app` is set as the working directory.
3. **Settings File**: The `settings.xml` file for Maven is copied to avoid downloading dependencies every time the build is run.
4. **Build Stage**: The project is built using Maven.
5. **Final Image**: The `openjdk:17-jre-slim` image is used for the final image, which is smaller and more secure.
6. **JAR File**: The built JAR file is copied from the build stage.
7. **Environment Variables**: `JAVA_OPTS` is set to use a secure random number generator for improved performance.
8. **Cron Job**: A cron job is scheduled to run the batch job at every hour (`0 * * * *`). The application is run with the `prod` profile.
9. **Cron Installation**: Cron is installed and configured to run the batch job.
10. **CMD**: The container starts cron and the application.

### Note:
- Replace `your-application.jar` with the actual name of your JAR file.
- Adjust the cron schedule (`0 * * * *`) as per your requirements.
- Ensure that the `settings.xml` file is correctly configured for your project if you are using a private repository or specific settings.
