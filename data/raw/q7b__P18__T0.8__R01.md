Here's a simple Dockerfile for a Go-based background worker using Asynq:

```dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.17-alpine AS builder

# Set the working directory in the container
WORKDIR /go/src/app

# Copy the go.mod and go.sum files
COPY go.mod go.sum ./

# Download all dependencies. Dependencies will be cached if the go.mod and go.sum files don't change.
RUN go mod download

# Copy the content of the local src directory to the working directory
COPY . .

# Build the Go app
RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -o main .

# Use a smaller base image for the production environment
FROM alpine:latest

# Create a working directory in the container
WORKDIR /root/

# Copy the binary file from the builder stage
COPY --from=builder /go/src/app/main .

# Expose the port on which the app will run
EXPOSE 8080

# Run the Go app
CMD ["./main"]
```

### Explanation:

1. **Builder Stage**:
   - `golang:1.17-alpine`: This is the Go language runtime image with Alpine Linux, which is a lightweight Linux distribution.
   - `WORKDIR /go/src/app`: Sets the working directory inside the container.
   - `COPY go.mod go.sum ./`: Copies the Go module files to the container.
   - `RUN go mod download`: Downloads all dependencies.
   - `COPY . .`: Copies the rest of the application code into the container.
   - `RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -o main .`: Builds the Go application, stripping unnecessary binaries and setting the output to `main`.

2. **Production Stage**:
   - `alpine:latest`: A lightweight base image for production.
   - `WORKDIR /root/`: Sets the working directory.
   - `COPY --from=builder /go/src/app/main .`: Copies the built binary from the builder stage into the production container.
   - `EXPOSE 8080`: Exposes port 8080.
   - `CMD ["./main"]`: Runs the Go application.

### Notes:
- Replace `8080` with the port your application is using if different.
- Ensure that your Go application is correctly set up to handle incoming tasks with Asynq.
- If you have additional configurations or environment variables, you can pass them using the `docker run` command.

This Dockerfile assumes that your Go application is already set up and built locally on your machine. If you need to build it within the Dockerfile, you can adjust the `COPY` and `RUN` commands accordingly.
