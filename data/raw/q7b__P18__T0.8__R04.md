Certainly! Below is a Dockerfile for a background worker built in Go using Asynq:

```Dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.17 AS builder

# Set the working directory in the container
WORKDIR /app

# Copy the go.mod and go.sum files
COPY go.mod go.sum ./

# Download all dependencies
RUN go mod download

# Copy the source code
COPY . .

# Build the Go application
RUN CGO_ENABLED=0 GOOS=linux go build -o main .

# Use a smaller image for the final container
FROM alpine:latest

# Set the working directory in the container
WORKDIR /root/

# Copy the built binary from the builder stage
COPY --from=builder /app/main .

# Set the command to run the application
CMD ["./main"]
```

### Explanation:

1. **Builder Stage (`builder`)**:
    - Uses an official Go 1.17 image to build the application.
    - Sets the working directory to `/app`.
    - Copies `go.mod` and `go.sum` to download all dependencies.
    - Copies the entire source code and builds the Go application into a binary named `main`.

2. **Final Stage**:
    - Uses an Alpine Linux image to create a minimal runtime environment.
    - Sets the working directory to `/root/`.
    - Copies the built `main` binary from the builder stage.
    - Sets the command to run the application using the `main` binary.

### Usage:

1. **Build the Docker Image**:
    ```sh
    docker build -t my-asynq-worker .
    ```

2. **Run the Docker Container**:
    ```sh
    docker run -d --name my-worker my-asynq-worker
    ```

This Dockerfile assumes that your Go application is correctly set up with Asynq and that the entry point of your application is a binary named `main`. Adjust the paths and dependencies as needed for your specific application.
