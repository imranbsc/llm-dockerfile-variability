Here's a simple Dockerfile for a Go-based command-line tool using Cobra:

```Dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.17 as builder

# Set the working directory in the container
WORKDIR /app

# Copy the go.mod and go.sum files
COPY go.mod go.sum ./

# Download all dependencies
RUN go mod download

# Copy the source code into the container
COPY . .

# Build the Go application
RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -o myapp

# Use a smaller image to serve the Go application
FROM alpine:latest

# Set the working directory in the container
WORKDIR /app

# Copy the built application from the builder stage
COPY --from=builder /app/myapp .

# Make the application executable
RUN chmod +x myapp

# Set the command to run the application
CMD ["./myapp"]
```

### Explanation:

1. **Base Image**: 
   - The first `FROM` instruction specifies the base Go image (`golang:1.17`). This is used to build the Go application.

2. **Working Directory**:
   - The `WORKDIR /app` instruction sets the working directory inside the container to `/app`.

3. **Go Dependencies**:
   - `COPY go.mod go.sum ./` copies the `go.mod` and `go.sum` files to the working directory.
   - `RUN go mod download` downloads all the dependencies required for the Go application.

4. **Build Application**:
   - `COPY . .` copies the rest of the Go source code into the container.
   - `RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -o myapp` builds the Go application. `CGO_ENABLED=0` ensures that the application is built without CGO, which is often necessary for building cross-platform applications. `GOOS=linux` specifies that the application should be built for Linux. The resulting binary is named `myapp`.

5. **Final Image**:
   - The second `FROM` instruction specifies the final image (`alpine:latest`). This image is smaller and more lightweight than the Go image.
   - `WORKDIR /app` sets the working directory inside the final container to `/app`.
   - `COPY --from=builder /app/myapp .` copies the built Go application from the builder stage into the final container.
   - `RUN chmod +x myapp` makes the application executable.
   - `CMD ["./myapp"]` sets the default command to run the application when the container is started.

This Dockerfile assumes that your Go application is structured correctly with a `main.go` file and a `cmd` directory for the command-line tool. Adjust the paths and filenames according to your specific application structure.
