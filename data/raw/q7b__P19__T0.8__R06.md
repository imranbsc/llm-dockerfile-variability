Certainly! Below is an example of a Dockerfile for a command-line tool built in Go using Cobra:

```Dockerfile
# Use an official Go runtime as a parent image
FROM golang:1.17 AS builder

# Set the working directory in the container
WORKDIR /app

# Copy the go.mod and go.sum files
COPY go.mod go.sum ./

# Download all dependencies
RUN go mod download

# Copy the rest of the application code
COPY . .

# Build the Go application
RUN go build -o mytool

# Use a minimal image to run the application
FROM alpine:latest

# Set the working directory in the container
WORKDIR /app

# Copy the built application from the builder stage
COPY --from=builder /app/mytool /app/mytool

# Make the application executable
RUN chmod +x /app/mytool

# Expose the application port
EXPOSE 8080

# Command to run the application
CMD ["./mytool"]
```

### Explanation:

1. **Builder Stage**:
   - Uses an official Go runtime image to build the application.
   - Sets the working directory to `/app`.
   - Copies the `go.mod` and `go.sum` files to download dependencies.
   - Downloads all dependencies using `go mod download`.
   - Copies the rest of the application code.
   - Builds the Go application into a binary named `mytool`.

2. **Final Stage**:
   - Uses a minimal Alpine Linux image to run the application.
   - Sets the working directory to `/app`.
   - Copies the built binary `mytool` from the builder stage.
   - Makes the binary executable.
   - Exposes port 8080 (you can change this as needed).
   - Sets the command to run the application.

### Building and Running the Docker Image:

1. Build the Docker image:
   ```sh
   docker build -t my-go-tool .
   ```

2. Run the Docker container:
   ```sh
   docker run -it --rm my-go-tool
   ```

This Dockerfile assumes that your Go application is structured correctly with a `main.go` file that uses Cobra. Adjust the paths and filenames as necessary to fit your specific project setup.
