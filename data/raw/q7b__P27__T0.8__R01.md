Certainly! Below is a Dockerfile for a server-rendered web application built in C# using ASP.NET Core MVC.

```dockerfile
# Use the official ASP.NET Core runtime image as the base image
FROM mcr.microsoft.com/dotnet/aspnet:6.0 AS base
WORKDIR /app
EXPOSE 80

# Use the official ASP.NET Core SDK image to build the application
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build
WORKDIR /src
COPY ["YourProjectName/YourProjectName.csproj", "YourProjectName/"]
RUN dotnet restore
COPY . .
WORKDIR "/src/YourProjectName"
RUN dotnet build "YourProjectName.csproj" -c Release -o /app/build

# Publish the application to a directory that will be used in the final stage
FROM build AS publish
RUN dotnet publish "YourProjectName.csproj" -c Release -o /app/publish

# Use the base image to create a lean, production-ready container
FROM base AS final
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "YourProjectName.dll"]
```

### Explanation:

1. **Base Image**: The `FROM mcr.microsoft.com/dotnet/aspnet:6.0 AS base` instruction specifies the base image for the runtime environment. This image contains the necessary files to run an ASP.NET Core application.

2. **Working Directory**: The `WORKDIR /app` instruction sets the working directory inside the container.

3. **Expose Port**: The `EXPOSE 80` instruction exposes port 80, which is the default port for HTTP traffic.

4. **Build Image**: The `FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build` instruction specifies the image to use for building the application. This image contains the necessary tools to build and publish an ASP.NET Core application.

5. **Working Directory for Build**: The `WORKDIR /src` instruction sets the working directory inside the build context.

6. **Copy and Restore**: The `COPY ["YourProjectName/YourProjectName.csproj", "YourProjectName/"]` and `RUN dotnet restore` instructions copy the project file and restore the NuGet packages.

7. **Copy and Build**: The `COPY . .` and `RUN dotnet build "YourProjectName.csproj" -c Release -o /app/build` instructions copy the source code and build the application in Release mode.

8. **Publish**: The `FROM build AS publish` instruction specifies the image to use for publishing the application. The `RUN dotnet publish "YourProjectName.csproj" -c Release -o /app/publish` instruction publishes the application to a directory that will be used in the final stage.

9. **Final Image**: The `FROM base AS final` instruction specifies the base image for the final production-ready container. The `COPY --from=publish /app/publish .` instruction copies the published application from the publish stage to the final stage. The `ENTRYPOINT ["dotnet", "YourProjectName.dll"]` instruction sets the entry point for the container to run the ASP.NET Core application.

### Usage:

To build and run the Docker container, follow these steps:

1. Save the Dockerfile in the root directory of your ASP.NET Core MVC project.
2. Build the Docker image:
   ```sh
   docker build -t your-project-name .
   ```
3. Run the Docker container:
   ```sh
   docker run -d -p 8080:80 --name your-container-name your-project-name
   ```

This will start a container running your ASP.NET Core MVC application on port 8080. You can access the application by navigating to `http://localhost:8080` in your web browser.
