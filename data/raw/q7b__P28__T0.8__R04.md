Certainly! Below is a Dockerfile for a background worker built in C# using the .NET Worker Service template.

```Dockerfile
# Use an official .NET SDK image as the base image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env
WORKDIR /app

# Copy csproj and restore as distinct layers
COPY *.csproj ./
RUN dotnet restore

# Copy everything else and build
COPY . ./
RUN dotnet publish -c Release -o out

# Use an official .NET runtime image as the final image
FROM mcr.microsoft.com/dotnet/aspnet:6.0
WORKDIR /app
COPY --from=build-env /app/out .

# Command to run the app
ENTRYPOINT ["dotnet", "YourWorkerService.dll"]
```

### Explanation:

1. **Base Image**: The Dockerfile starts with an official .NET SDK image to build the application. Replace `6.0` with the version of .NET you are using.

2. **Working Directory**: The working directory is set to `/app`.

3. **Copy .csproj and Restore**: The `.csproj` file is copied to the container and restored. This ensures that only the dependencies are restored.

4. **Copy Project Files and Build**: All project files are copied, and the application is published in Release mode to the `out` directory.

5. **Final Image**: A smaller, read-only .NET runtime image is used for the final image. Again, replace `6.0` with the version of .NET you are using.

6. **Copy Published Files**: The published files from the build stage are copied to the final image.

7. **Entry Point**: The application is started with the `dotnet` command, running `YourWorkerService.dll`. Replace `YourWorkerService.dll` with the name of your worker service DLL.

### Usage:

1. **Build the Docker Image**:
   ```sh
   docker build -t your-worker-service .
   ```

2. **Run the Docker Container**:
   ```sh
   docker run -d --name your-worker-container your-worker-service
   ```

This setup ensures that your background worker is containerized and ready to run in a Docker environment.
