Here is a Dockerfile for a background worker built in C# using the .NET Worker Service template:

```dockerfile
# Use the official .NET SDK image to build and publish your application
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env
WORKDIR /app

# Copy csproj and restore as distinct layers
COPY *.csproj ./
RUN dotnet restore

# Copy everything else and build
COPY . ./
RUN dotnet publish -c Release -o out

# Use the official .NET runtime image to create a slim image for your app
FROM mcr.microsoft.com/dotnet/aspnet:6.0
WORKDIR /app
COPY --from=build-env /app/out .

# Expose the port that your app runs on
EXPOSE 5000

# Start the app
ENTRYPOINT ["dotnet", "YourAppName.dll"]
```

Replace "YourAppName.dll" with the name of your compiled .NET Worker Service application.

### Explanation:

1. **mcr.microsoft.com/dotnet/sdk:6.0**: This is the base image for building the application. It includes the .NET SDK, which is necessary for compiling and publishing the C# code.

2. **WORKDIR /app**: Sets the working directory inside the container to `/app`.

3. **COPY *.csproj ./**: Copies the `.csproj` file(s) to the working directory and runs `dotnet restore` to download the necessary NuGet packages.

4. **COPY . ./**: Copies the entire contents of the local directory into the container.

5. **dotnet publish -c Release -o out**: Publishes the application in Release mode and places the output in the `out` directory. The `-o out` option specifies the output directory.

6. **mcr.microsoft.com/dotnet/aspnet:6.0**: This is the base image for running the application. It only includes the .NET runtime, which is smaller and more secure than the SDK image.

7. **WORKDIR /app**: Sets the working directory inside the container to `/app`.

8. **COPY --from=build-env /app/out .**: Copies the published output from the build stage into the container.

9. **EXPOSE 5000**: Specifies the port that the application will listen on.

10. **ENTRYPOINT ["dotnet", "YourAppName.dll"]**: Specifies the command to run the application when the container starts. Replace `YourAppName.dll` with the actual name of your application DLL.

### Building and Running the Docker Image:

1. Build the Docker image:
   ```sh
   docker build -t your-worker-service-image .
   ```

2. Run the Docker container:
   ```sh
   docker run -d -p 5000:5000 your-worker-service-image
   ```

This setup will create a Docker image that contains your background worker and run it in a container.
