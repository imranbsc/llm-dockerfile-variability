Certainly! Below is a Dockerfile for a C# command-line tool built with `System.CommandLine`.

```Dockerfile
# Use an official .NET SDK image as the base image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory inside the container
WORKDIR /app

# Copy the project file and restore dependencies
COPY *.csproj ./
RUN dotnet restore

# Copy the entire project source code
COPY . ./

# Build the application
RUN dotnet publish -c Release -o out

# Use a smaller .NET runtime image as the final image
FROM mcr.microsoft.com/dotnet/aspnet:6.0

# Set the working directory inside the container
WORKDIR /app

# Copy the published application from the build stage
COPY --from=build-env /app/out .

# Make the application executable
ENTRYPOINT ["dotnet", "YourAppName.dll"]
```

### Explanation:

1. **Base Image (`build-env`)**:
   - `FROM mcr.microsoft.com/dotnet/sdk:6.0`: Uses the official .NET SDK image to build the application.
   - `WORKDIR /app`: Sets the working directory inside the container.
   - `COPY *.csproj ./`: Copies the project file to the working directory.
   - `RUN dotnet restore`: Restores the project dependencies.
   - `COPY . ./`: Copies the entire project source code.
   - `RUN dotnet publish -c Release -o out`: Publishes the application in Release mode and outputs it to the `out` directory.

2. **Final Image**:
   - `FROM mcr.microsoft.com/dotnet/aspnet:6.0`: Uses a smaller .NET runtime image to keep the final image size minimal.
   - `WORKDIR /app`: Sets the working directory inside the container.
   - `COPY --from=build-env /app/out .`: Copies the published application from the build stage.
   - `ENTRYPOINT ["dotnet", "YourAppName.dll"]`: Specifies the entry point for the application.

### Usage:

1. **Build the Docker Image**:
   ```sh
   docker build -t your-app-name .
   ```

2. **Run the Docker Container**:
   ```sh
   docker run -it --rm your-app-name
   ```

Replace `YourAppName.dll` with the actual name of your published application DLL file.
