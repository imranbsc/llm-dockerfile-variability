Certainly! Below is an example of a Dockerfile for a command-line tool built in C# using System.CommandLine:

```Dockerfile
# Use an official .NET SDK image as the base image
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build-env

# Set the working directory in the container
WORKDIR /app

# Copy the project file and restore dependencies
COPY *.csproj ./
RUN dotnet restore

# Copy the rest of the project files and build the project
COPY . ./
RUN dotnet publish -c Release -o out

# Use a smaller, non-sdk base image to create the final container
FROM mcr.microsoft.com/dotnet/aspnet:6.0

# Set the working directory in the container
WORKDIR /app

# Copy the published application from the build stage
COPY --from=build-env /app/out ./

# Make the application executable
RUN chmod +x MyCommandLineTool

# Set the entry point to run the application
ENTRYPOINT ["./MyCommandLineTool"]
```

### Explanation:
1. **Base Image**: The `FROM mcr.microsoft.com/dotnet/sdk:6.0` line specifies the base image for the build stage. This image includes the .NET SDK and is used to build the application.

2. **Working Directory**: `WORKDIR /app` sets the working directory inside the container.

3. **Copy Project Files**: The `COPY *.csproj ./` and `RUN dotnet restore` commands copy the project file and restore the dependencies.

4. **Copy and Build Application**: `COPY . ./` copies the rest of the project files, and `RUN dotnet publish -c Release -o out` builds and publishes the application to the `out` directory.

5. **Final Image**: The `FROM mcr.microsoft.com/dotnet/aspnet:6.0` line specifies a smaller, non-sdk base image for the final container. This image is used to run the application without the SDK.

6. **Copy Published Application**: `COPY --from=build-env /app/out ./` copies the published application from the build stage to the final stage.

7. **Make Executable**: `RUN chmod +x MyCommandLineTool` ensures that the application is executable.

8. **Set Entry Point**: `ENTRYPOINT ["./MyCommandLineTool"]` sets the command to run the application when the container starts.

### Customization:
- Replace `MyCommandLineTool` with the actual name of your command-line tool executable.
- If your project has specific dependencies, make sure to include them in the `csproj` file and restore them during the build stage.

This Dockerfile should work for a typical C# command-line application using System.CommandLine.
